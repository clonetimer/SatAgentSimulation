# CALIBRATION WITHOUT REAL DATA STRATEGY

## Purpose

This document defines how the project should proceed when real ground-test, vendor test, or flight calibration datasets are not available.

The core rule is:

```text
No real calibration data -> no ground_calibrated or flight_correlated claim.
```

The simulation may still be useful for architecture validation, sensitivity screening, scenario generation, and early engineering estimates, provided the parameter confidence level is explicitly bounded.

## Evidence ladder

| Evidence class | Allowed confidence | Typical source | Permitted use |
|---|---|---|---|
| synthetic_only | demo | Generated data used only to test pipelines | Tooling, CI, examples |
| bounded_assumption | demo / engineering_estimate with approval | Explicitly documented assumption and range | Early trade studies |
| public_literature | engineering_estimate | Papers, handbooks, public spacecraft/component examples | Sensitivity/UQ priors |
| vendor_datasheet | engineering_estimate | Datasheet min/typ/max values | Engineering estimate |
| design_derived | engineering_estimate | CAD, mass properties, electrical sizing, geometry | Pre-test model building |
| low_cost_bench | ground_calibrated only for measured parameters | Small bench tests, power meters, thermistors, spin-down logs | Parameter calibration with limited scope |
| formal_ground_test | ground_calibrated | Acceptance/qualification test data | Engineering validation |
| flight_telemetry | flight_correlated | In-orbit telemetry and operations logs | Flight correlation |

## Rules

1. Synthetic data may validate the pipeline but must not upgrade parameter confidence.
2. Datasheets and literature may support engineering estimates, not ground calibration.
3. Bounded assumptions must have explicit lower/nominal/upper values and rationale.
4. If a parameter is mission-sensitive and uncalibrated, reports must surface it as a risk.
5. If a model lacks the necessary physics, parameter fitting must not be used to hide the model gap.

## Practical fallback workflow

```text
1. Classify every required parameter by evidence class.
2. Assign conservative uncertainty bounds.
3. Run sensitivity / UQ to identify dominant parameters.
4. Design minimal acquisition tests only for dominant parameters.
5. Keep low-sensitivity parameters as wide engineering priors.
6. Report parameter confidence separately from mission success.
```

## Minimal data acquisition options

| Subsystem | Minimal feasible evidence when formal calibration data is missing |
|---|---|
| ADCS inertia | CAD mass properties plus conservative inertia uncertainty |
| RW / CMG | Spin-up/spin-down logs, current telemetry, motor command response |
| IMU | Static six-position data, Allan variance from logged stationary data |
| Magnetometer | Rotational sweep in known local field, hard/soft iron fit |
| CSS | Lamp/solar simulator angular sweep, relative response curve |
| EPS load | Power meter measurements by operating mode |
| Battery | Charge/discharge curve at fixed load and temperature |
| Solar panel | Datasheet I-V plus illumination/angle derating assumptions |
| Comm/Data | Datasheet TX power, antenna gain pattern, modem BER curve, ground station geometry |
| Thermal | Heater step response with thermistors and ambient logging |
| Propulsion | Datasheet thrust/Isp/min impulse; no ground-calibrated claim without test data |

## Profile handling

When real data is unavailable, create a separate registry such as:

```text
configs/parameters/engineering_estimate_registry_v1.json
```

Each record should include:

```json
{
  "parameter_id": "comm_data.transmitter.tx_power_w",
  "confidence": "engineering_estimate",
  "source_type": "vendor_datasheet",
  "source_ref": "DATASHEET-ID-OR-URL-HASH",
  "value": 5.0,
  "unit": "W",
  "uncertainty": {
    "distribution": "triangular",
    "lower": 4.0,
    "mode": 5.0,
    "upper": 6.0
  },
  "validity": {
    "temperature_c": [-10, 40],
    "extrapolation_allowed": false
  },
  "approval_status": "reviewed"
}
```
