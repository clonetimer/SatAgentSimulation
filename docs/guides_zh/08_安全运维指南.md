# 安全运维指南

## 1. 认证模式

- `disabled`：仅限本机和隔离开发环境；
- `token`：普通服务器和远程 Worker 必须使用。

角色：

| 角色 | 权限 |
|---|---|
| viewer | 读取能力、任务和结果 |
| operator | 创建 TaskSpec、提交/取消仿真 |
| worker | 只访问绑定 Worker ID 的远程执行接口 |
| admin | 平台管理和健康详情 |

## 2. Token 管理

- 每个角色和 Worker 使用独立 Token；
- Token 长度建议至少 256 bit 随机熵；
- 环境文件权限设为 `600`；
- 不把 Token 写入 Git、日志、TaskSpec 或 Run Bundle；
- 定期轮换；
- Worker 下线后立即撤销其 Token。

可生成摘要：

```bash
export TEMP_TOKEN='实际Token'
python -m sat_sim.cli token-sha256 --token-env TEMP_TOKEN
unset TEMP_TOKEN
```

## 3. TLS

远程 Worker 必须通过 HTTPS 连接。正式环境禁止 `--insecure-skip-tls-verify`。

## 4. 文件权限

建议：

```text
/etc/sat-sim/*.env      600 root:root
/etc/sat-sim/auth.json  600 root:root
/var/lib/sat-sim        750 sat-sim:sat-sim
/var/lib/sat-sim-worker 750 sat-worker:sat-worker
```

控制面和 Worker 使用不同系统用户。

## 5. 上传和解压安全

远程结果必须经过：

- 最大体积限制；
- 最大压缩比限制；
- ZIP 路径穿越检查；
- 符号链接拒绝；
- `run_id` 匹配；
- ExecutionPlan SHA-256 匹配；
- `SEALED.json` 存在；
- 全部制品哈希验证。

## 6. 审计日志

审计日志记录身份、角色、路径、方法、状态和授权结果，不记录：

- Bearer Token；
- 模型 API Key；
- 完整请求体；
- 完整模型 Prompt。

建议接入集中日志，并设置保留和访问策略。

## 7. 备份

至少备份：

- SQLite 队列数据库；
- 正式 `runs/`；
- 认证与 Provider 配置的加密备份；
- 发布源码包和校验文件。

备份时应暂停写入或使用 SQLite 在线备份机制，避免直接复制正在写入的数据库文件。

## 8. 已知边界

当前 Token 模式不是企业统一身份系统；SQLite 不是高可用分布式队列；普通共享文件系统的一致性依赖部署环境。面向公网或多租户生产部署时，应增加 OIDC、数据库高可用、对象存储和集中密钥管理。
