## 阻断项一：主动/被动姿态约定混用

原实现把 Basilisk q_BN 在传给 Hamilton 渲染四元数前共轭。Basilisk EP2C(q_BN) 表示被动 N→B 方向余弦矩阵，而同一组四元数分量按 Three.js 主动约定生成的矩阵已经是 EP2C(q_BN)^T。额外共轭导致非零姿态的方向被反转。

修正规则：C_GB = C_GE C_EN C_BN^T；在 Hamilton 主动四元数乘法中，机体项直接使用原始 Basilisk EP 分量。只在 THREE.Quaternion 构造处把 scalar-first 调整为 x/y/z/w。

本条纠正原 2026-11-14-p9h-native-attitude-globe.md 中 H3 第 2 条“先取逆”的表述；B/N 命名不变，转换时必须区分矩阵映射方向和四元数的主动/被动解释。

独立本地测试：单位姿态及 X/Y/Z 三轴正负 90°。旧实现 1 PASS / 6 FAIL，修复后 7 PASS / 0 FAIL；同时检查 q/-q 等价。测试通过实际 scene 文件的公开转换函数执行，不用该函数本身生成期望值。

新增 CI 原生交叉校验：20 组四元数（含复合姿态、MRP 非主集与 q/-q）对照实际 Basilisk EP2C(q)^T。原有真实 UI、原生 recorder、场景和长时回归继续保留。

## 阻断项二：封存 Run 姿态的端到端支持仍不完整

当前 dataset_writer.py 的 scene_support_fields 仅保留位置三轴；app.js 的 telemetry overview 场景支持字段也仅请求位置三轴。控制器测试手动提供带姿态的 rows，证明了显示函数能消费它们，不证明真实有限 Run 在选择其他曲线时仍保存和读取姿态。

剩余验收必须覆盖：真实 Basilisk 有限 Run → writer 保存姿态 → seal/integrity → overview 返回位置和姿态同样本 → Chromium 实际模型旋转与检查器。不得把合成 rows 测试称为上述端到端验收。

当前组合定姿算法在后端已有传感器融合链路；尚未接入的是数字场景的估计姿态输出与对比展示，不应描述为全平台尚无组合定姿算法。
