# P9-F：Basilisk 遥测驱动的卫星数字地球场景

## 目标

将现有离线 Globe.gl 场景从独立演示轨道升级为真实 Basilisk 轨道遥测驱动的数字地球场景。演示模式保留为明确标识的无仿真备用模式。

## 事实与坐标约定

- Basilisk 统一整星记录器的 `orbit.position_m_x/y/z` 来源于 `state.r_BN_N`，即惯性参考系 N 下的位置向量。
- Globe.gl 使用地理纬度、经度和相对地球半径的高度。
- 通过遥测对应的 UTC epoch + 仿真时间，采用 GMST 地球自转角将 ECI/N 位置近似转换到 ECEF，再按 WGS-84 椭球求地理坐标。
- epoch 必须从 Run TaskSpec 或实时会话的实际初始轨道配置读取；不允许用浏览器当前时间替代仿真 epoch。
- 缺失/非法位置或 epoch 时不更新真实卫星位置，也不回退为“真实”标识。

## 实施批次

### P9-F1：真实遥测接入
- 连续整星会话的遥测订阅契约加入三轴轨道位置字段。
- 有限实时整星会话的默认遥测流加入三轴轨道位置字段。
- 实时会话元数据公开只读 `orbit_epoch_utc` 与 `orbit_frame=N_INERTIAL`。
- 两种实时控制台复用已有 WebSocket/遥测拉取链路，不新增 socket、定时轮询或第二套遥测缓存。
- 从实时控制台切换到三维场景时，后台保留当前实时源的只读遥测订阅；离开场景后按原导航生命周期关闭订阅/轮询。

### P9-F2：三维地球坐标与轨迹
- 从 ECI/N 向量和 UTC epoch + sim_time 计算地球固定坐标。
- 使用 WGS-84 椭球求纬度、经度、高度。
- 使用真实样本更新卫星标记与地面轨迹；按有界样本数保留路径。
- 真实遥测源切换时清理旧源轨迹，避免跨会话/Run 混线。
- 场景状态明确区分实时会话、封存有限 Run 和演示轨道；不以演示轨道覆盖已接入的真实数据。
- 真实数据接管时停止演示轨道动画；无真实数据时才显示显式标注的演示轨道。

### P9-F3：有限 Run 结果接入
- 整星 Run 的 trace 保留用于三维定位的内部轨道位置字段，不改变用户选定曲线和 QoI。
- 仅从成功、封存且完整性校验通过的 Run 启用结果回放。
- 对抽样遥测标注“轨迹概览/抽样”，不声称为完整原始轨迹。
- Run ID 切换时清空旧轨迹，拒绝过期响应覆盖。

### P9-F4：验收
- JavaScript：ECI→ECEF→WGS-84 测试向量、地球自转、epoch/时间处理、非法数据拒绝、轨迹边界和源切换。
- Python：会话 epoch/frame 元数据、实时 telemetry stream position contract、trace scene-support 字段。
- Chromium：真实场景加载、实时位置驱动、真实轨迹更新、演示模式与真实模式标签区分、无外网请求。
- 回归 P9-C 场景生命周期、P9-D 对象配置、P9-E Run 结果、实时会话和 Basilisk 原生测试。

## 严格边界

- 不改动 Basilisk 动力学、轨道初始条件、姿态控制或仿真执行节奏。
- 不把演示轨道、SGP4 预测或浏览器自行推演当作仿真遥测。
- 不为部件臆造三维位置；本阶段首先定位整星质心/轨道位置。
- 对象树选中某单机不代表已拥有该单机的空间锚点；只有经审定的安装位置/姿态映射才能显示部件模型节点。
- 继续复用现有 Globe.gl 离线资产和真实遥测传输链路。
