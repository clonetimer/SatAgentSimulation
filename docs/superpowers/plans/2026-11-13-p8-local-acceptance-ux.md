# P8：本地验收反馈修复

## 用户实测问题

- 向导第四步点击校验后无法运行，用户只看到通用失败提示，缺少可直接修正的字段/后端校验原因。
- 选择单独部件（本次为反作用轮）后，限时实时和持续实时不可用，但入口原因不够明确，容易被理解为两类实时功能缺失。
- 拖拽建模入口藏在折叠的专业工具区域，用户未能发现。

## 本轮修复

1. 校验失败时将字段/后端校验摘要带回向导提示；仍以 previewForm() 返回值决定能否运行，不绕过校验。
2. 实时模式继续遵循服务端 interactive/capabilities policy。单独部件不伪造实时能力，提示用户改选已注册的分系统或整星；持续实时不支持的组合显示具体策略原因。
3. 向导顶部增加独立“拖拽式建模”入口，直接打开现有 Graph Composer，不复制或重写建模执行链。

## 验收边界

- 本次改动不改变 Basilisk 物理模型、TaskSpec schema、实时会话 API、执行队列或安全策略。
- 反作用轮作为单独部件是否可独立实时运行，仍以 Capability Registry 和服务端 policy 为准；不能因为用户希望看到入口就开放未注册后端。
- 必须通过新增静态 UX 契约测试、既有向导/实时浏览器回归、真实有限 Basilisk 回归后，才能合并。
