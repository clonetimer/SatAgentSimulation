# P9-A 仿真与效能评估解耦实施计划

> 执行方式：当前会话内执行，三个独立文件域，公共接口集中审查。

## 已确认方向与本轮范围

用户要求结果指标退出仿真对象树，按实际记录的输出进行独立效能评估，由用户或开发者确认配置调整。本轮选择只读后处理边界，不采用仿真循环内评分或自动调参。

- 仿真工作区：对象、物理配置参数、过程输出、运行状态、故障事件和必要的安全/数值检查。
- 评估工作区：引用运行记录、数据快照、评估方案及版本、公式与适用条件；输出评估结果，不修改原始数据、TaskSpec 或运行状态。
- 数据统计摘要不等同效能结论；均值、极值、末值是后处理统计，没有阈值或任务目标时不产生合格/不合格结论。
- 参数 Owner 可以是整星、分系统、单机、环境、外部设施或链路；所属与关联引用分开。轨道环境和轨道控制继续分开。
- 现有 summary/QoI 字段保留为历史兼容数据，不删除已经归档的证据，不把 summary 字段自动解释成效能评分。
- 更改评估方案不触发重跑。缺少所需输出时说明无法评估；补录输出需要用户明确创建新运行。
- 不自动应用参数建议；用户选择复制配置后，新任务仍走原有校验和执行入口。

## 三个任务的文件与接口边界

### A：后处理契约

创建独立、无运行器依赖的评估模块和测试。只接受调用方提供的已记录序列及其 run_id/快照标识，计算显式选定的统计公式；记录方案版本与输入引用，不写文件、不创建会话、不改变仿真结果。

### B：对象树契约

修改 workbench_object_tree.py：物理树仅包含参数和过程输出，移出 summary_group；保留稳定对象/源字段 ID，更新结构版本。整星、分系统、设备及链路适用相同规则。输入不能被修改，树必须可序列化。

### C：界面消费契约与回归

增加与对象树版本配套的只读界面视图模型：仿真面板只展示参数/过程量，评估面板独立接收后处理结果，不能用评分代替运行状态。现有默认工作台的完整入口迁移另行联调，不用隐藏卡片冒充完成解耦。

## 执行与验收顺序

- [ ] 新增失败测试，覆盖结果指标退出对象树、原始输入不变及评估独立性。
- [ ] 将现有 P9-A 专项测试显式纳入 CI；核实之前绿色工作流是否运行这些测试。
- [ ] A/B/C 分别实现并验证，公共契约变更集中提交。
- [ ] 测试缺字段、单位冲突、NaN、空窗口、重复 ID、重评不改原始运行、用户未确认不回写。
- [ ] 检查命名字典是否随安装包分发，避免源码环境通过而安装后导入失败。
- [ ] 更新旧对象树断言，保留原有运行校验、模型能力、TaskSpec 和 Basilisk 回归。

## 边界

不新增未经确认的效能权重、合格阈值或控制律。不把采样均值称为时间加权均值。不将本批纯后处理单元测试称为物理仿真验收。不合并 main，最终记录准确提交及 CI 状态。
