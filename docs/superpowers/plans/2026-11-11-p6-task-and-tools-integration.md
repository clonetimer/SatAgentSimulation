# P6：任务与专业工具整合——对话引导与专业画布融合

## 目标

以用户任务完成效率为验收对象，统一专业工具的入口、上下文、引导和返回路径；不把需要空间操作的工具强制改成聊天气泡，也不复制第二套业务控制器。

## P6-A：拖拽式建模与对话引导融合（第一批实施）

### 用户旅程

1. 用户从对话工作台选择“图形化建模”。
2. 进入专业画布后，先看到建模助手：说明当前状态、下一步建议和快捷动作。
3. 用户可从模块库拖拽节点、连接类型化端口、编辑参数；专业画布仍是唯一真实编辑器。
4. 助手按当前节点/连线状态提示下一步；快捷动作调用现有图编辑器操作。
5. 正式校验仍调用服务端 `/tasks/compile-graph`，通过后才能生成代码或运行。

### 第一批功能

- 在原图形工作区顶部增加“建模助手”，不创建平行画布。
- 助手状态区区分前端结构检查、服务端正式编译校验和 Python 生成一致性；服务端编译成功后明确显示“正式校验已通过”，图/参数变更后清除旧校验状态。
- 基于当前 Capability、节点数、连线数和本地结构检查结果给出下一步提示。
- 快捷操作：定位模块库、恢复推荐流程（覆盖前确认）、自动布线（覆盖连线前确认）、触发正式后端校验。
- 恢复/自动布线/校验继续调用原函数和服务端接口；不绕过端口类型、DAG、TaskSpec、能力边界与运行前检查。
- 专业画布、模块库、节点属性、任务流程/多模块装配、代码生成和运行能力全部保留。

### 本轮测试补充

- 在真实 Chromium 紧凑工具栏回归中验证建模助手可见、下一步标题/说明非空，点击“选择模块”后焦点进入模块库搜索框。
- 扩展真实 Chromium 图形交互：恢复推荐流程（确认覆盖）、自动布线（确认替换连线）、调用服务端 compile-graph 正式校验、拖拽节点移动、撤销与重做。
- 助手状态区现在区分“前端结构通过待正式校验”“服务端正式校验通过待生成代码”“代码与图参数一致可运行”，不再把本地结构检查误称为后端验证。
- 该浏览器测试继续覆盖任务流程与多模块装配两种模式的工具栏、键盘操作和窄屏布局。

### 验收

- 从向导进入图形建模后能立即理解下一步。
- 空画布、未选择能力、结构错误、结构通过待后端校验、代码新鲜等状态提示准确。
- 快捷动作实际调用原控制器；覆盖性操作有确认。
- 拖拽节点、连线、节点属性编辑、撤销/重做仍正常。
- Chromium 验证对话入口 → 建模助手 → 拖拽/连接 → 正式校验；服务端校验仍为最终权威。

## P6-B：任务中心融入对话工作区

- 将任务搜索、状态筛选、任务详情、版本、运行历史、克隆、编辑、重跑和删除组织为单一任务工作区。
- 保留不可变版本语义和既有 API；不将历史 Run 伪装为新运行。

## P6-C：自然语言与 TaskSpec 融合

- 自然语言解析仍走现有 Agent provider/解析服务。
- 图形建模可从用户描述生成候选 TaskSpec/图形初始结构，但必须展示变更预览。
- 用户确认后再应用到原图编辑器；不直接执行模型生成代码，不绕过后端 compile/validate。

## P6-D：专业工具入口与上下文整合

- 批量实验、目标实验、系统诊断、运行对比、快速调参保留专业工作区。
- 对话工作区提供任务导向入口、当前上下文摘要、返回和结果引用。
- 不把高密度专业图表和复杂参数强塞进聊天气泡。

## 全阶段安全边界

- 不修改 Basilisk 物理模型、Capability Registry、TaskSpec schema 或 Run Bundle schema。
- 不复制图形状态机或在助手内维护第二份节点/连线状态。
- 不绕过端口类型、DAG、服务端能力校验、参数预检和运行安全门禁。
- 不自动运行、不自动覆盖用户图；恢复推荐流程和自动布线在覆盖现有内容前必须确认。
- 专业工具功能不能因对话式改造而删除。



## P6-B：任务中心对话式工作区（第一批）

- 向导内任务卡片将高频操作“任务详情、编辑配置、运行任务”放在主操作区。
- “克隆任务、删除任务”收进“更多操作”折叠区，减少每张任务卡片的按钮密度；删除仍保留二次确认。
- 任务详情仍通过原控制器读取任务版本和运行历史；打开指定版本仍投影到原配置表单，运行仍生成独立 Run。
- 任务版本不可变、克隆新建独立任务、历史 Run Bundle 不因删除任务而删除的既有语义保持不变。
- 新增真实 Chromium 回归：向导打开历史任务、展开次级操作、克隆任务、查看任务版本详情。


## P6-C：TaskSpec 与图形建模衔接（第一批）

- TaskSpec 工作区增加“应用并在图形画布中查看”入口；自然语言生成并投影到分步配置后，也可从配置区直接打开图形画布。
- 入口先复用现有 `syncEditorToForm()`，将经过现有解析/校验路径的 TaskSpec 投影到 canonical form。
- 随后进入原图形编辑器；当前 Capability 相同则保留现有图形编辑状态，不同则在重建推荐流程前提示覆盖。
- 图形画布仍是原生节点/端口/DAG 编辑器；任务参数、事件和输出由已应用配置驱动，正式校验仍调用原后端 `compile-graph`。
- 此入口不自动生成 Python、不自动运行、不执行未经用户确认的图形覆盖。
- 新增静态契约测试，冻结 TaskSpec 投影、图形工作区切换和覆盖确认路径。

## P6-D：专业工具统一入口与返回路径（第一批）

- 对话工作台“其他专业工具”增加运行中心入口，帮助用户区分任务配置与实际 Run Bundle。
- 实验中心、目标实验、系统诊断、运行中心增加统一“返回仿真向导”操作。
- 返回时保留当前向导步骤、配置、任务版本与运行记录；显示返回提示，不重置用户上下文。
- 各专业工具仍保留自身完整布局、数据表、预算/验证逻辑和既有控制器，不强行塞入聊天气泡。
