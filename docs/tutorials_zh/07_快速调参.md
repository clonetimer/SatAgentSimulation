# 07｜快速调参

## 本课目标

不手工反复“改参数 → 运行 → 记结果”，让 V15 自动跑少量候选并按一个 QoI 排序。

快速调参不是通用优化器，它适合工程上的小范围快速搜索。

---

# 1. 约束先记住

V15 快速调参当前限制：

- 1–3 个参数；
- 每参数 2–5 个候选；
- 总组合数最多 12；
- 参数必须是 Capability Schema 已注册的数值参数；
- 目标必须是已注册 QoI；
- 支持 minimize / maximize。

---

# 2. 用 ADCS 做第一个调参练习

加载：

```text
ADCS + Reaction Wheel · 可运行组合
```

打开：

```text
快速调参
```

选择目标：

```text
qoi.adcs.final_pointing_error_deg
```

方向：

```text
minimize
```

第一次只选一个参数，例如界面提供的：

```text
control_kp_nm_per_rad
```

候选值先用两个，例如：

```text
0.08
0.12
```

> 如果当前 Schema 给出的范围与示例不同，以界面 min/max 为准，不要强行输入越界值。

---

# 3. 启动扫描

系统会生成两个真实 Run，而不是在浏览器里算一个公式。

完成后会给出排名，例如：

```text
Candidate A  → final pointing error = ...
Candidate B  → final pointing error = ...
Best         → ...
```

---

# 4. “调参最优”是什么意思

扫描完成后，最佳 Run 可以作为结果参考，但当前模型参数还没有自动改变。

因此 V15 会把它标成：

```text
调参最优
```

而不是假装它就是当前模型。

---

# 5. 真正应用最优参数

确认结果后点击：

```text
应用最优参数
```

此时：

- 参数写回当前模型；
- 旧 TaskSpec 变 stale；
- 旧生成代码变 stale；
- 需要重新生成 Python / 构建运行。

这是正确行为，因为模型语义真的变了。

---

# 6. 什么时候不要用快速调参

不适合：

- 几十个参数；
- 大规模全局优化；
- 每个 Run 很昂贵；
- 需要贝叶斯优化/TPE 等专业搜索算法。

V15 这个入口的定位是：**小规模、可解释、快速工程比较。**
