# 故障排查指南

## 1. `No module named sat_sim`

确认已安装或设置源码路径：

```bash
python -m pip install -e '.[api]'
python -c 'import sat_sim; print(sat_sim.__file__)'
```

## 2. Basilisk 导入失败

```bash
python -c 'import Basilisk; print(Basilisk.__path__)'
python -m pip show bsk
```

项目固定 `bsk==2.11.0`。不要同时安装冲突的同名包。

## 3. Doctor 提示 WMM/SPICE 缺失

完整源码包应包含：

```text
third_party/wmm/WMM2025.COF
third_party/spice/de430.bsp
```

也可显式设置：

```bash
export SAT_SIM_ASSET_ROOT=/path/to/assets
export SAT_SIM_WMM_PATH=/path/to/WMM2025.COF
export SAT_SIM_SPICE_PATH=/path/to/spice
```

## 4. 页面可打开但 API 返回 401/403

- 401：缺少或无效 Bearer Token；
- 403：Token 有效，但角色不足；
- Worker 403：Worker Token 与 URL 中 `worker_id` 不一致。

## 5. Worker 长时间不认领任务

检查：

```bash
python -m sat_sim.cli queue-status --database /var/lib/sat-sim/control/execution_queue.sqlite3
journalctl -u sat-sim-remote-worker -n 200
```

确认控制面 URL、TLS、Token、Worker ID、系统时间和网络连通性。

## 6. 任务停留在 RUNNING

- 查看 Worker 心跳和租约；
- 查看 Worker 子进程日志；
- 检查磁盘空间；
- 检查 Basilisk 是否在长时场景中运行；
- 租约失效后由队列对账，不应手工编辑数据库。

## 7. 控制面拒绝远程结果

常见原因：

- ZIP 含路径穿越或符号链接；
- 上传体超过限制；
- `run_id` 不一致；
- 执行计划哈希不一致；
- 缺少 `SEALED.json`；
- 制品哈希不一致；
- 终态不是允许状态。

## 8. Provider 未就绪

- 检查配置文件路径；
- 检查 `enabled`；
- 检查 `base_url` 和模型名；
- 检查 `api_key_env` 对应变量是否存在；
- 使用 `model-providers --live-probe`；
- 不要把自动 fallback 的模板结果当作真实模型结果。

## 9. Windows 解压或路径错误

使用本次标准源码包，不要使用混有大小写重复文件的历史归档。建议解压到较短路径，例如：

```text
D:\sat-sim-既有版本
```

## 10. 测试命令超时

先区分“测试失败”和“外部命令通道停止等待”。对于长时 Basilisk 用例，应保留 pytest 进程、日志和退出码，等待真实终态；不能以超时日志为空为依据判定通过。

## 11. Windows 启动报错：`FastAPI object has no attribute add_event_handler`

这是旧启动钩子与本机 FastAPI/Starlette 组合不兼容导致的。当前代码使用 `lifespan` 协议；若仍出现该问题，应先核对实际安装版本与锁文件。

先检查当前环境：

```powershell
.\scripts\check_api_stack.ps1
```

若仍使用旧虚拟环境，直接重建：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\repair_windows_environment.ps1
.\scripts\start_local_windows.ps1
```

也可手工删除 `.venv` 后重新执行 `bootstrap_windows.ps1`。不要只升级单个 FastAPI 包，因为 FastAPI、Starlette、Uvicorn 和 HTTPX 需要按项目约束共同安装。
