## 首轮范围与基线

采用工作台的正式名称。**离线仿真**（`offline`）执行到指定仿真时长并返回运行结果。**限时实时仿真**（`limited_realtime`）提供交互控制，到达设定时长自动结束。**持续实时仿真**（`continuous_realtime`）持续输出遥测，由用户停止并归档。实时会话还受服务端能力目录和部署配置约束。首轮使用原生整星作为共同对象，另外抽查仅开放离线的单机对象是否给出正确的入口限制。[工作台实现](../../src/sat_sim/web/app.js)

## 执行顺序与验收

1. **先打通表单的三种模式。** 使用 uv 环境锁定 Python、原生 Basilisk、浏览器和服务配置，保存能力目录。冻结同一整星案例的能力 ID、历元、非默认三轴初始角速度、采样间隔及种子。对限时任务记录结束时间，对持续任务记录人工停止时刻。逐模式核对用户输入、服务端实际配置及 Basilisk 首帧，登记单位、坐标系、采样时刻和比较容差。先用这个基准定位运行后端差异。
2. **逐入口补齐其余 12 格。** 从真实浏览器操作发起。JSON 核对导入字段；拖拽核对图节点和参数；数字场景核对所选对象、操作后创建的会话和遥测来源；自然语言核对真实请求、首答、重试、修复、调用次数、耗时和 token 来源。检查入口切换后参数是否被默认模板重置。若只能导出到其他入口，记录实际操作链，并单列直接启动缺口。
3. **验收运行生命周期。** 离线核对结束时间、验证报告、封存及历史回放。限时实时核对暂停期间仿真时间、单步推进、继续、遥控响应、自动结束及归档。持续实时核对实时帧、断开后重连到同一会话、主动停止及归档。异常中止保留日志和已有证据，并验证可以重建场景。短程矩阵与耐久资格分开记账。
4. **修复与回归。** 各格分别记录代码 SHA、部署配置、请求、Run/Session ID、原生首帧、末帧、验证结果和可校验的制品。区分“通过”“失败”“按能力设计受限”“缺证待验”。能力设计受限需要同时核对界面说明、服务端原因和未误启动其他模式。约定支持的整星组合缺失按功能缺口处理。先修共用参数传递，再修入口特有问题；在同一候选提交重跑受影响组合，保留初始失败记录。

**交付条件**：15 格均有可复核的结论，按模式列出成功数、承诺支持数和剩余缺口。任何承诺支持但未通过的组合保留为未完成；资格报告另列测试环境及能力边界。
