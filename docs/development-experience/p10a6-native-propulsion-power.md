# P10-A6 推进辅助电负载接入经验

日期：2026-11-20。状态：实现与本地原生专项完成；合并验收以关联 PR
最终提交的 CI 记录为准。本页只记录已观察到的结果。

## 第一段：共享状态适配器与推荐整星运行路径

- **改了什么：**每只推进器使用独立的活动状态适配器和官方
  `SimplePowerSink`，同一电功率消息进入电池与原有热节点。总功率来自
  每只官方节点的实际 recorder；保留逐推进器证据。
- **为什么：**旧桥使用 `20 W × thrustFactor`，但项目没有这条电功率曲线
  的硬件依据。本次采用明确的固定辅助电负载工程假设，工作时计入、
  待机为零；不是化学能、排气功率或推进效率模型。
- **发现的实际问题：**`permissionStatusOutMsg` 仅限制首次点火命令。
  许可后来撤销不会取消已下发的燃烧，旧桥却因此把仍在工作的推进器
  电负载清零。新节点依据实际 `thrustFactor` 活动，不读取启动许可作电源开关。
- **输入边界：**未写入的启动消息允许 t=0 `NOT_READY`；运行期间缺失、
  非有限数、越界因子均关闭该节点并报告错误，不允许静默归零后宣称成功。
- **已完成验证：**基线原生测试 10 passed；新增专项先得到 12 failed / 1 passed，
  其中真实整星用例复现许可撤销后的漏记功耗；修复后官方 Basilisk 2.11.0
  专项 13 passed。功耗开/关 A/B 的推力、耗油与轨道保持一致，电池和热控有对应响应。

## 第二段：Composite 接入与累计电能

- **改了什么：**另一条整星路径同样使用逐推进器官方电负载节点；
  `propulsion_power_w` 从任务入口传入实际构图。保持结构热节点位置和
  `propulsion.actual_activity` 来源标识，累计电能取每个动力学步的原生功率。
- **为什么：**输出采样间隔可能长于燃烧脉冲。用显示采样积分会漏掉
  实际用电；按动力学记录的分段常值功率积分，可保持粗细输出一致。
- **原生证据：**单只推进器工作 0.8 s、辅助负载 20 W 时记录 16 J；
  第二只关闭时无额外负载。仅关闭电负载节点的 A/B 中，原生推力、燃料、
  位置、速度、姿态记录逐元素一致，电池电量差等于推进电能。
- **验证：**此段及既有 ADCS/通信/Payload/加热器、七条资源耦合专项
  20 passed。推荐路径的事件、密封 Run Bundle 和实时配置回归 103 passed。

## 第三段：独立审查后的修正

1. **任务入口遗漏参数：**直接构图支持新参数，并不证明普通任务入口已接入。
   实际适配器执行测试先复现请求 17 W 却得到默认 20 W，补齐映射和范围校验。
2. **短脉冲证据漏采：**同一 0.8 s 燃烧在 3 s 输出间隔下没有显示样本。
   增加逐动力学步的官方状态/功率 recorder，验收统计独立于导出间隔。
3. **实时分段与内存：**每个量子完成后累积固定大小的功耗统计；每只
   状态适配器保留最近 256 条诊断与最早 10 条错误详情，累计错误数不截断。
   量子比导出间隔短时，也必须独立清理已汇总的快记录；否则会重复统计。
   60 个 0.2 s 量子的回归先复现 933 个重复样本，修正后要求真实的 121 个样本。
4. **热源同名覆盖：**多个官方节点沿用同一个热源标识时，瞬时来源诊断
   必须按标识求和；原赋值会让最后一只关闭的推进器把第一只的 20 W 覆盖成零。
5. **零瓦不等于耦合已激发：**允许配置零电负载，但显式资源响应要求应返回
   `INCONCLUSIVE`，不能仅因存在推力就声称观测到电热响应。

上述修正均观察到预期失败再修复。修正后的两条推进路径、资源信任与
参数审计共 **45 passed**。更早阶段的一个恒定加热器正功率断言已失效：
P10-A5 删除了该代理，暖态恒温器关闭时必须如实记录无加热刺激。

  114 个脚本，0 errors / 0 warnings。
- 本次最终提交的原生长回归、独立 Run Bundle 与浏览器验收，
  以对应 PR 的最终 CI 结果为准。
- 本地首次完整专项为 102 passed / 2 failed：手动抽取 workflow 命令时
  漏带其 `PYTHONPATH=src:.` 环境，两个原生子进程无法导入 `sat_sim`。
  重跑时完整继承该步骤的环境；不改测试或生产导入逻辑来掩盖执行配置问题。
- 本地真实 Chromium 的 9 个场景均停在浏览器启动。独立最小验证确认
  执行环境禁止 `AF_UNIX` socket（`EPERM`），Chromium 的 process singleton
  因此 `SIGABRT`，尚未进入页面。已有启动参数不能解决此环境限制；
  不计作产品验收通过，以最终提交的 GitHub Actions 真实 Chromium 门禁补齐。

## 资源复查中确认的既有边界

- 在未修改的主干 `61a0ab2d` 与官方 Basilisk 2.11.0 上，Composite 冷启动
  t=0 电池 recorder 为 0 J/0 J；后续原生积分正确，但旧报告以该样本作初值，
  把 518400 J 初始储能计为残差，导致整体能量/物理/执行验收失败。
  关闭推进器也可复现，分支与原主干相同。本次没有放宽守恒或 SOC 标准；
  推进功耗 A/B 通过不等于该路径整体通过。这是下一项资源验收修复任务。
- Composite 热桥在热任务时刻采样瞬时功率。0.8 s 脉冲在 0.2 s 热步长下
  得到 13.6 J 热输入，但默认 10 s 热步长可能完全漏采。该限制在原主干
  也存在；本次仅证明已解析热步长下的电热响应，不声明任意热步长的脉冲热量守恒。

## 持续适用的边界

额定辅助电负载和 0.85 电能到局部热量的分配比例仍是工程假设。使用官方
电负载模块、工程功率代理数量为零，不代表实测阀门电流、飞行标定、
电推进效率或燃烧/羽流热模型已经得到验证。
