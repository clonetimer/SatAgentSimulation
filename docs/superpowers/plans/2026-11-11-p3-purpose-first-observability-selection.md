# P3：曲线与观测指标选择重构

## 目标

将“选择输出”从一份混合的字段勾选清单，重构为两个清晰、相互独立但共享观测目的与搜索条件的选择器：
- 结果指标（QoI）：描述一次运行的摘要表现。
- 时序曲线（Telemetry）：描述仿真过程中随时间变化的遥测量。

## 交互结构

### 1. 观测目的
- 由当前能力 Schema 的 QoI 与 trace 注册目录动态生成可用目的标签。
- 支持姿态与控制、能源与功耗、热控与温度、通信与数据、轨道与环境、任务与整星状态及其他。
- 目的分类只决定 UI 过滤，不新增、不改名、不伪造遥测字段；不匹配的字段归入其他。
- 某目的只有在当前能力实际存在匹配注册字段时才显示。

### 2. 结果指标（QoI）
- 使用 summary_options 生成独立指标卡片。
- 显示中文名称、说明、单位和按需展开的技术字段名。
- 选择结果只写入 outputs.qoi。

### 3. 时序曲线（Telemetry）
- 使用 trace_options 生成分系统分组卡片。
- 先显示分组、选中数量和整组添加/移除，再按需展开具体曲线。
- 单条曲线显示含义、单位和技术字段名。
- 时间轴继续由现有 time_s 结果契约提供，不把时间轴当作需要勾选的纵轴参量。
- 选择结果只写入 outputs.plots。

### 4. 搜索与推荐组合
- 一个搜索框同时搜索 QoI 和时序曲线的名称、描述、单位及分组信息。
- 显示匹配指标数和匹配曲线数；无匹配时给出明确提示。
- “恢复模型推荐组合”读取当前 Schema default_form.outputs；不使用前端硬编码的指标或曲线列表。
- 高级目录继续保留完整摘要指标与完整遥测字段，供专业用户逐项检查。

## 数据与执行边界
- 所有选项来自 Capability Registry 派生的 summary_options / trace_options。
- UI 目的标签只做确定性归类和筛选；不改变 schema、QoI 名称、trace 名称、单位或来源。
- QoI 只修改 outputs.qoi；时序曲线只修改 outputs.plots；互不覆盖。
- 恢复推荐组合只读取当前能力 schema 的默认输出配置。
- 任一选择变化都会清除旧 TaskSpec / planning，并使上一次正式校验失效。
- 不改变 Run Bundle、遥测采集、结果数据或 Basilisk 执行链。

## 验收
- 静态测试确认两个选择器分别使用 summary_options 和 trace_options。
- Chromium 测试验证目的过滤、技术字段搜索、推荐组合恢复及选择状态。
- 运行前校验与既有真实运行回归保持通过；UI 测试不替代物理验收。
