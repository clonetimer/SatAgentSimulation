## 1. 判定规则

本矩阵按代码、真实运行证据和产品入口分别判定。单纯存在参数、YAML 声明、测试定义或配置蓝图，不算真实模型已运行。

| 标记 | 含义 |
|---|---|
| 已验证 | 当前代码路径有真实执行或真实浏览器证据，且结论严格限定在证据覆盖范围内 |
| 部分实现 | 有可执行实现，但物理范围、产品接入、运行条件或验证覆盖不完整 |
| 仅配置/实验 | 有接口、蓝图或实验性路径，尚不足以作为正式产品能力 |
| 未实现 | 当前主干未发现满足该要求的实现 |
| 待量化 | 已有基础，但缺少明确的任务指标、误差预算或性能实测 |

“已验证”不等于飞行验证、硬件标定或任务级精度合格。各能力的模型来源必须继续区分 Basilisk 官方原生、项目自研原生模块、工程代理和参考几何。

## 5. DT-0 结论

1. 现有平台已经具备真实 Basilisk 执行、部分环境模型、整星闭环、Run Bundle 和三模式数字场景的工程基础。
2. 目前最大物理差距集中在 NRLMSISE、J3/J4、统一 SRP/阻力环境耦合、器件非理想特性的全链路覆盖及独立工具 V&V。
3. 目前最大前端差距不是基础三维渲染，而是统一场景对象、CAD 安装映射、多窗时间联动、数据规模和操作回溯。
4. 当前性能等级为 soft_realtime；硬实时、PTP/IRIG-B 和分布式星座尚不能作为已实现能力宣传。
5. 首期应以一颗 LEO 卫星的完整、可验证工程闭环为目标，不同时铺开数百星、深空和 HIL。
