## 1. 阶段编号对齐

当前仓库存在两套 P9-B 命名：产品设计文档将 Cesium 技术 Spike 称为 P9-B；而实际实施 PR #125/#126 已将独立效能评估工作区称为 P9-B。为避免后续 PR、CI、验收报告和用户沟通出现同名异义，采用以下实施编号：

| 阶段 | 工作流 | 验收边界 |
|---|---|---|
| P9-A | 对象树、对象归属、参量字典 | 对象语义和真实字段来源 |
| P9-B | 独立效能评估与配置反馈 | 已封存 Run 的只读评估、独立报告、用户确认配置草稿 |
| P9-C | 三维数字场景技术 Spike | Cesium 最小 Viewer、地球、卫星资产、轨道、相机、离线降级 |
| P9-D | 对象拾取与空间锚点 | 对象树/场景双向选择、锚点定位、fallback 区域 |
| P9-E | 对象配置与参量面板 | Schema 参数、单位、校验状态、对象归属 |
| P9-F | 离线结果联动 | Run Bundle 真实数据、对象过滤、事件与曲线 |
| P9-G | 两种实时仿真联动 | 真实 Basilisk 会话状态和遥测驱动场景 |
| P9-H | 默认入口收敛与专业入口保留 | 普通用户完整旅程、V15 专业建模回归 |

此编号只统一实施路线，不改变已创建 PR 的编号或历史记录。原 P9 设计文档中的三维技术 Spike 对应本文件 P9-C；后续阶段顺延。

## 2. P9-C 目标与非目标

### 目标

在现有前端工作台中建立独立、可销毁、可恢复的 Cesium 场景组件，证明以下链路可行：

1. 本地可启动真实三维地球；
2. 可加载有来源与许可证记录的卫星 GLB/glTF 资产；
3. 可显示明确标识为“显示轨道”的轨道线；
4. 可使用同一场景时间源驱动卫星演示位置；
5. 可执行跟踪卫星、解除跟踪、返回全景；
6. 在无外部地图 Token、断网或在线影像不可用时降级到随包低分辨率地球纹理；
7. Viewer 初始化失败、WebGL 不可用、资源加载失败时，工作台仍可用并显示可理解的降级状态。

### 非目标

- 不接入真实实时遥测，不把演示动画称为实时仿真；
- 不实现对象树与三维部件拾取；
- 不实现整星精细 CAD 模型或部件空间锚点；
- 不修改 Basilisk、TaskSpec、Capability Registry、运行队列、Run Bundle；
- 不替换默认首页，不删除 V15；
- 不引入 Cesium ion 运行时 Token 或必须联网的地图依赖。

## 3. 技术决策与公开案例依据

### 3.1 引擎

采用 CesiumJS 作为 P9-C 的地理空间 Viewer 候选。技术 Spike 必须核对仓库当前构建方式、依赖许可、浏览器兼容和打包体积后再锁定具体版本。

选型理由：
- 地球椭球、影像图层、场景时间和相机控制是核心原生能力；
- glTF/GLB 是卫星资产格式；
- Entity/Polyline/时间属性适合表达轨道与时变位置；
- 后续可通过模型节点拾取和显式 anchor manifest 承接 P9-D。

公开案例：
- NASA Eyes 提供浏览器三维地球/太阳系/航天器探索、时间控制与任务观察参考：https://science.nasa.gov/eyes/
- NASA 对 Eyes 的说明强调航天器模型、轨迹、时间回溯/前推与自由探索：https://www.nasa.gov/centers-and-facilities/jpl/explore-the-solar-system-with-nasas-new-and-improved-3d-eyes/
- CesiumJS 官方离线指南说明可关闭默认在线服务，并使用本地 Natural Earth II 纹理或自有影像服务：https://github.com/CesiumGS/cesium/blob/main/Documentation/OfflineGuide/README.md
- CesiumJS 官方 Model 文档说明 glTF 模型能力与模型加载方式：https://cesium.com/learn/cesiumjs/ref-doc/Model.html
- OGC 3D Tiles 标准适合后续大规模异构三维地理数据流式加载，但不是 P9-C 首批必需依赖：https://github.com/CesiumGS/3d-tiles/blob/main/specification/Specification.adoc

### 3.2 资产与离线策略

- 首批只需要一个轻量、可合法再分发的示意卫星模型；资产来源、许可证、文件大小、坐标轴方向、单位、原点和缩放必须记录在 manifest。
- 模型缺失时使用明确的程序化占位卫星，不使用外部随机模型，不影响场景启动。
- 使用 Cesium 自带低分辨率 Natural Earth II 纹理作为无网络回退；禁止默认依赖在线影像、地形、地理编码或未配置 Token。
- 在线高分辨率地球资源只能作为显式可选项，加载失败时自动回退并显示当前图层来源。
- 云层、昼夜和高精度地形不作为首批验收阻塞项；先验证地球、卫星、轨道和相机的基础正确性。

## 4. P9-C 模块边界

建议新增独立前端模块，按仓库现有静态资源组织方式落位，不把所有场景逻辑继续堆入 app.js：

- scene/cesium-runtime：Viewer 初始化、销毁、资源加载与错误恢复；
- scene/earth-layer：本地地球底图和可选在线图层；
- scene/satellite-asset：模型加载、占位模型和资产 manifest；
- scene/orbit-visual：轨道线及演示时间采样；
- scene/camera-controller：跟踪、解除跟踪、返回全景；
- scene/scene-status：加载、降级、WebGL 不可用和资源错误状态。

Viewer 生命周期必须绑定工作台挂载/卸载，避免重复创建 WebGL context、事件监听器或 request-render 循环。场景时间与仿真时钟接口分离；P9-C 仅使用演示时钟，后续 P9-G 才能接入服务端真实时钟。

## 5. 数据真实性分层

所有场景元素必须显式携带来源类型，至少区分：

- `illustrative_asset`：示意模型资产；
- `illustrative_orbit`：演示轨道；
- `demo_clock`：演示场景时钟；
- `simulation_telemetry`：真实仿真遥测（P9-G 以后才允许）；
- `archived_run_data`：真实归档运行数据（P9-F 以后才允许）。

P9-C 的卫星运动和轨道线必须在界面和数据结构中标记为演示内容。不得把演示轨道参数写回 TaskSpec，不得把演示位置暴露为运行结果或遥测。

后续实时联动必须满足：每个更新样本包含仿真时间、接收时间、序列号、来源会话和数据新鲜度；无新帧时保留上一帧并标记陈旧，不推进伪造位置。

## 6. P9-C 验收标准

### 功能

1. 工作台进入场景时只创建一个 Viewer；离开后正确销毁。
2. 地球、卫星和轨道均可见，且轨道标签明确为演示轨道。
3. 跟踪卫星、解除跟踪、返回全景可重复操作。
4. 用户手动旋转/缩放/平移时，不被后台演示时钟强制抢回镜头。
5. 本地离线资源可用；断网时不出现持续请求失败或空白主视图。
6. 在线图层失败后能回退到本地纹理。
7. WebGL 不可用或模型加载失败时有可理解的降级提示，其他工作台功能仍可用。
8. 不发起仿真 API，不创建 Run，不更改 TaskSpec 或现有实时会话。

### 自动化

- JS 单元/契约测试：Viewer 生命周期、重复挂载、资源失败回退、时间来源标记、相机状态切换。
- 浏览器 Chromium：桌面视口、窄视口、DPR 变化、导航进入/退出、离线拦截外部请求。
- 资源治理：资产许可证/来源 manifest、文件大小预算、依赖锁定和构建产物检查。
- 既有 P7/P8 浏览器与 Basilisk 工作流必须保持通过；P9-C 本身不改变物理模型，因此不以物理结果数值变化作为验收目标。

### 性能基线

记录 Viewer 首次可见时间、模型加载时间、场景稳定帧率、JS heap、GPU/WebGL 资源释放情况。先在项目现有 Windows Chromium 验收环境建立基线，不预先编造固定性能阈值；根据实际机器基线和可重复测试结果设定门槛。

## 7. 并行与依赖

- P9-A 对象/参量合同继续独立收尾；P9-C 不等待所有 1507 项源字段审定。
- P9-B 效能评估独立推进；不依赖三维 Viewer。
- P9-C 只消费只读 presentation manifest，不将资产节点映射反向作为物理对象定义。
- P9-D 才将对象树 object_id 与模型 node/anchor 绑定。
- P9-F/P9-G 分别复用现有 Run Bundle 与 Interactive Session，不创建第二套结果库或仿真执行器。

## 9. 风险控制

- 不以视觉完成度代替物理真实性；
- 不以截图代替可交互浏览器测试；
- 不把在线地图服务可访问等同于离线部署可用；
- 不将模型 mesh 数量或模型名称直接推断为真实设备安装数量；
- 不把轨道演示插值或动画时钟作为仿真时钟；
- 不合并尚未通过最新 CI 的 P9-A/P9-B 变更；
- 不因场景开发而中断现有 P7/P8 用户流程和 V15 专业建模能力。
