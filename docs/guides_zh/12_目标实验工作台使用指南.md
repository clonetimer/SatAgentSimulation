# 目标实验工作台使用指南

## 1. 功能定位

“目标实验”用于围绕一个工程目标组织多轮仿真。与单次仿真或普通参数扫描不同，GoalRun 会把基础任务、允许修改的参数、成功条件和累计预算绑定在同一个目标下，并记录每轮实验、运行状态、证据分析与决策。

典型流程：

1. 选择一份已校验的 TaskSpec。
2. 写明工程目标，指定允许调整的参数和成功条件。
3. 设置整个目标的实验数、运行数、执行尝试数和模型调用数预算。
4. 创建并激活目标。
5. 在目标允许的参数范围内创建实验轮次。
6. 预览候选后启动真实仿真。
7. 读取运行状态与证据，进行确定性分析或大模型辅助解释。
8. 审阅下一轮建议，决定是否创建新实验。

模型建议不会自动绕过预算、能力注册表或验证器，也不会因为分析结论而修改已封存的运行证据。

## 2. 创建目标

进入左侧导航 **目标实验**，选择“新建目标”。

### 2.1 目标描述

使用可验收的工程表述，例如：

> 在满足末端 SOC 不低于 0.35、负载卸载次数为 0 的条件下，比较不同电池容量，找出候选范围内的最小可行容量。

避免只写“优化电源系统”这类无法判断完成与否的描述。

### 2.2 基础任务

可以选择：

- 当前已经校验的配置；
- 任务中心中保存的任务。

基础 TaskSpec 创建后作为目标的固定基线。后续实验只能修改目标创建时批准的参数路径。

### 2.3 允许调整的参数

参数列表来自当前能力注册表和实验参数选项。建议只开放本轮研究确实需要变化的参数，例如：

- `parameters.values.battery_capacity_wh`
- `simulation.duration_s`

不需要变化的轨道、初始状态、控制器、故障和模型配置应保持不变。

### 2.4 成功条件

可配置指标、比较关系和目标值。示例：

| 指标 | 关系 | 目标值 |
|---|---|---:|
| `final_soc` | `>=` | 0.35 |
| `load_shed_event_count` | `==` | 0 |

成功条件是目标级验收条件，不会覆盖 Run Bundle 中已有的物理、安全和完整性检查。

### 2.5 总预算

预算对整个目标累计生效：

- 实验数：允许创建的实验轮次数；
- 运行数：允许提交的仿真变体总数；
- 执行尝试数：允许的 worker 执行尝试总数；
- 模型调用数：允许的证据解释等模型调用总数。

预算应按预计实验轮次预留，不要把单轮预算误认为整个目标预算。

## 3. 创建实验轮次

打开目标详情，在“创建下一轮实验”中：

1. 填写实验名称和本轮验证目的。
2. 选择目标允许修改的参数。
3. 输入候选值，使用逗号分隔。
4. 点击“预览候选”。
5. 检查变体数量、候选值和预算余额。
6. 点击“创建本轮实验”。

例如电池容量候选 `120,160,200` 会生成三种参数变体。候选值仍需满足参数注册表规定的类型、范围和单位。

实验创建后尚未运行。只有点击“启动本轮运行”才会向执行队列提交真实仿真。

## 4. 启动和恢复运行

启动时系统会：

- 检查目标剩余运行预算和执行尝试预算；
- 为每次提交绑定 operation ID；
- 复用确定性 run ID 和现有 Durable Execution Queue；
- 将 operation、experiment、variant 和 run 关联；
- 对提交超时、进程中断等情况执行状态对账。

如果界面提示“提交未确认”，先刷新目标详情核对运行状态。不要通过新建实验或更换 operation ID 来盲目重试。

目标预算与运行队列是不同层级的状态：目标取消不等同于强制终止已经提交的所有仿真运行。需要停止具体运行时，应到运行中心使用相应的取消操作。

## 5. 证据分析

目标详情支持两种分析方式：

### 确定性证据分析

由程序读取运行指标、事件、断言、验证状态和证据引用，不调用大模型。适合核对数值、比较候选和检查证据完整性。

### 大模型辅助解释

在已配置并通过完整测试的模型服务中选择 Provider。模型可以：

- 总结各轮实验差异；
- 解释哪些约束已满足、哪些仍未满足；
- 区分观测事实、对比结果和待验证假设；
- 提出下一轮候选参数或补充实验建议。

模型输出是建议，不是执行授权。创建下一轮实验仍需检查参数白名单、预算和计划预览。

## 6. 决策记录与状态

目标详情保留按顺序追加的决策记录，包括目标创建、实验创建、运行提交、证据分析和停止决策。记录中的 evidence 字段提供可追溯引用。

目标终态由服务端根据实际状态确定。用户取消目标后，不再允许继续为该目标创建新实验或追加预算；已经提交的运行仍按各自 Run 状态管理。

## 7. 当前功能边界

- 当前工作台支持参数扫描（sweep）主流程；更复杂的 Monte Carlo 设计仍可通过现有实验中心使用。
- 大模型不会任意修改未登记参数路径。
- 大模型不会自动扩大目标预算。
- 证据不完整时，系统应返回部分结果或待核实状态，不得将其解释为目标完成。
- 目标协调状态恢复不等同于跨进程恢复整星物理求解器状态。
- Basilisk 仿真结果仍受当前能力实现等级、模型假设和 Run Bundle 验证范围约束；不构成真实硬件或飞行资格证明。

## 8. 常见问题

**创建目标时提示没有可调整参数**

检查基础 TaskSpec 是否对应已登记能力，以及参数是否属于可扫描标量参数。对象型配置和未登记字段不会作为可修改参数开放。

**实验创建成功但没有运行**

这是正常状态。创建实验只保存变体，需在实验卡片中单独启动运行。

**运行提交超时**

刷新目标详情核对 operation、run 和队列状态；同一操作应使用原 operation ID 恢复，不要创建新的实验来掩盖未知状态。

**模型解释与指标不一致**

以 Run Bundle、comparison、assertion 和 traceability 证据为准。模型解释不能覆盖程序计算的数值，也不能把相关性直接写成因果关系。
