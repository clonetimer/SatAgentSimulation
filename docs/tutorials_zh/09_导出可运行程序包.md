# 09｜导出可运行程序包

## 本课目标

把“只能在网页里运行的图”变成一个别人可以拿走的 Python 项目。

---

# 1. 先确保当前模型是你要交付的版本

建议按顺序：

```text
校验
  ↓
生成 Python
  ↓
构建并运行一次
  ↓
确认结果
  ↓
导出可运行程序包
```

---

# 2. 导出的 ZIP 里有什么

典型内容：

```text
my_simulation_program/
├── run_simulation.py
├── task_spec.json
├── visual_graph.json 或 assembly_graph.json
├── program_manifest.json
├── run.sh
├── run.bat
└── README.md
```

### 这些文件分别是什么

`run_simulation.py`  
实际运行入口。

`task_spec.json`  
模型编译后的标准任务描述。

`assembly_graph.json` / `visual_graph.json`  
图形工程信息。

`program_manifest.json`  
程序包元数据、合同 fingerprint、module selection 等。

`run.sh` / `run.bat`  
启动脚本。

---

# 3. 怎么运行导出的程序包

导出包**不包含整个 Python/Basilisk runtime**。

所以要在已经安装匹配 SAT 环境的机器上运行。

Linux/macOS：

```bash
bash run.sh
```

Windows：

```bat
run.bat
```

通用方式：

```bash
python run_simulation.py
```

---

# 4. 为什么推荐 `bash run.sh`，而不是 `./run.sh`

ZIP 解压工具不一定可靠保留 Unix executable bit。

所以：

```bash
bash run.sh
```

跨解压工具更稳。

---

# 5. Scope 会不会进入交付程序？

Scope/Display/To Workspace 工程信息会保存在图工程中，方便以后重新打开。

但它们：

```text
observer_runtime_effect = none
```

不会进入物理 runner，也不会改变 TaskSpec。

---

# 6. 推荐交付内容

正式交付一个仿真任务时，建议至少保存：

```text
程序包 ZIP
V15 版本/commit
运行环境 Python 版本
依赖锁文件/可用 wheelhouse
代表性 Run ID 或 Run Bundle
验收结果说明
```
