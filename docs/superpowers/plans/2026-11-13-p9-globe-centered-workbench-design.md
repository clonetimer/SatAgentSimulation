# P9：地球场景驱动的卫星仿真工作台产品设计

- 状态：设计基线（待用户确认对象层级语义后冻结）
- 日期：2026-11-13
- 基线：main / P8（7dffea0）
- 设计决定：真实地球；卫星沿轨道运动；镜头自动跟踪并允许自由操作；V15 保留为独立专业入口
- 本文只定义产品、交互、数据和迁移设计，不改变现有仿真物理模型与执行链

## 1. 产品目标与非目标

### 1.1 产品目标

将默认仿真入口从“表单/图编辑器工作台”重构为“以卫星数字场景为中心的任务工作台”。

用户应能在同一主场景中完成：
1. 选择整星、分系统或单机；
2. 观察被选对象在卫星上的真实空间位置；
3. 配置该对象已注册的仿真参数；
4. 选择离线、限时实时或持续实时运行；
5. 查看当前选中对象实际记录的结果；
6. 在场景与对象间切换，不需要跳转到旧表单页面。

### 1.2 非目标与必须保留的边界

- 不重写 Basilisk 动力学、FSW、部件模型、TaskSpec、执行队列、Run Bundle 或验证规则。
- 不用前端动画代替真实仿真；实时场景只能由服务端实际仿真时间、位置、姿态与遥测驱动。
- 离线仿真结果展示不要求卫星模型随结果回放；未来可增加显式“结果回放”，但不纳入第一版。
- 不把尚无实时执行合同的部件伪装成可实时运行。
- V15 图形化建模/多模块装配保留为独立专业入口，不再作为普通用户创建仿真的主路径。
- 不展示开发日志、内部 API、reason code、TaskSpec/ExecutionPlan/Run Bundle 等实现术语；技术细节仅在高级诊断或证据视图按需查看。

## 2. 产品信息架构

主工作台采用三栏空间布局，地球场景占据主视觉区域。

### 2.1 左侧：仿真任务助手

默认宽度约 300–360 CSS px，可折叠。仅显示用户当前需要的步骤：
- 任务目标：正常仿真 / 故障仿真 / 查看历史结果；
- 对象范围：整星 / 分系统 / 单机；
- 对象选择与搜索；
- 运行方式：离线 / 限时实时 / 持续实时（依据服务端能力显示状态与原因）；
- 创建、校验、运行、停止等任务操作；
- 自然语言需求输入作为可选入口，生成候选配置后必须由用户检查和确认。

对话内容必须是任务语言，不展示“当前对话框”“复用旧页面”“调用现有图编辑器”等实现描述。

### 2.2 中央：三维地球与卫星场景

- 真实地球纹理、昼夜明暗、云层/大气效果与星空背景。
- 一颗任务卫星沿其轨道运动，默认黄色虚线轨道；卫星是镜头跟踪目标。
- 初次进入采用有节制的入场镜头：从地球全景平滑靠近卫星，不自动高速旋转。
- 用户可旋转、缩放、平移；提供“跟踪卫星”和“返回全景”两个明确相机操作。
- 选择分系统/单机时，镜头先平滑定位到卫星，再放大至对应区域；如果模型没有可精确定位的子部件锚点，则高亮所属区域或显示标注，不得伪造三维位置。
- 可配置部件使用可点击名称标签；标签避免重叠，近距离/远距离采用不同密度策略。
- 选中对象以高亮轮廓、引导线和名称标识；非选中部件降低视觉权重。
- 场景中只保留必要信息：卫星名称、轨道、选中对象、运行状态与时间。其他信息按需展开。

### 2.3 右侧：对象上下文面板

默认宽度约 360–440 CSS px，可折叠。面板由“对象 + 工作状态”决定，不是固定表单。

配置态：
- 对象名称、所属分系统、模型说明（用户语言）；
- 参数按物理意义分组，默认仅显示常用项；
- 每个参数展示中文名称、当前值、单位、有效范围、简短物理含义；
- 专业参数按需展开；
- 修改后显示“尚未校验”，通过正式配置校验后才可运行；
- 保存/恢复模型默认值。

运行态：
- 只展示当前选中对象的实际输出；
- 顶部为关键数值卡片（带单位与数据时间）；
- 下方为该对象可用曲线、事件和状态；
- 曲线默认最多展示 2–4 条，可搜索、切换和添加；
- 离线运行展示最终结果与完整时间序列；限时/持续实时展示当前值、滚动曲线和数据新鲜度；
- 切换对象时，右侧面板切换对应数据；不改变仿真任务或会话。

## 3. 对象层级与空间映射

### 3.1 用户对象树

统一对象树：

```
整星
├── 姿态控制分系统
│   ├── 反作用轮 1..N
│   ├── 控制力矩陀螺
│   ├── 星敏感器
│   ├── 太阳敏感器
│   ├── 惯性测量单元
│   ├── 磁强计
│   └── 磁力矩器
├── 轨道与空间环境（单独显示，不并入姿态控制）
│   ├── 轨道状态/轨道传播
│   ├── 轨道摄动与空间环境
│   └── 轨道相关观测量
├── 电源分系统
├── 热控分系统
├── 推进分系统
├── 载荷分系统
└── 通信与数据管理分系统
```

这是产品层级目标，不代表每个节点都已有独立执行模型。目录必须把“可独立配置运行”“作为所属分系统的一部分配置”“仅可观察”区分清楚。

### 3.2 当前源码事实与需要整改的层级问题

当前 `workbench_catalog.py` 将六个分系统定义为：ADCS（中文名为“姿态与轨道控制”）、推进、电源、热控、载荷、通信与数据管理；轨道与空间环境则作为独立的 `orbit_environment` 对象。该定义导致姿态与轨道在用户层级被合并，和本次产品要求不一致。

P9 必须：
- 将 ADCS 用户名称改为“姿态控制分系统”；
- 将“轨道与空间环境”作为独立一级对象/分系统入口展示；
- 明确区分轨道动力学/传播、空间环境模型、姿态确定与控制；
- 不把“轨道控制”一词直接等同于轨道动力学或轨道传播；
- 轨道对象暂时复用真实注册的 `orbit_environment.orbit_fidelity.v1` 能力；没有独立轨道控制执行合同的功能不标成可独立控制；
- 在后续对象模型中新增明确的 parent/child、spatial_anchor、configuration_scope、execution_capability、observable_fields 元数据。

### 3.3 空间锚点与模型资产

每个可定位部件应由一个资产映射描述：
- `object_id`：稳定产品对象 ID；
- `parent_object_id`：父级对象；
- `model_asset`：整星 glTF/GLB 资产；
- `node_name` 或 `anchor_id`：模型内部节点/锚点；
- `fallback_anchor`：没有精确节点时的所属区域锚点；
- `camera_profile`：全景、对象近景、局部观察距离；
- `pickable` / `label_visible`：是否可选与显示标签；
- `capability_ids`：可用于配置的能力合同；
- `telemetry_owner_ids`：实际输出字段的归属对象。

资产映射是显示层元数据，不得反向决定物理模型或伪造部件拓扑。三维模型未准备好时，使用明确的低保真占位模型，不隐藏对象、不编造精确部件位置。

## 4. 三维场景技术方案

### 4.1 技术选型

优先采用 CesiumJS：
- Globe / Imagery / Atmosphere / Sun lighting：地球与空间环境；
- glTF/GLB：卫星及其可分选的模型节点；
- Entity / Primitive / Polyline：卫星轨道、标签、选择高亮与引导线；
- SampledPositionProperty 或等价时间属性：将真实时间采样位置映射到卫星运动；
- Camera tracking 与自定义相机控制：跟踪卫星，同时允许用户解除跟踪自由操作。

选择 CesiumJS 的理由是其已提供地球、时变实体、glTF 模型、虚线轨迹、对象拾取与相机跟踪所需的基础能力。具体 API 与版本需在技术 Spike 中按仓库依赖和浏览器支持验证。

### 4.2 真实地球与数据源

- 第一版使用可离线缓存/可配置的地球影像资源；禁止把产品启动强依赖某个未授权在线地图 Token。
- 云层可作为独立影像/球壳层，昼夜边界与太阳光照按场景时间计算。
- 资源需明确许可证、来源、缓存策略、分辨率和离线降级方案。
- 初始版本不要求全球高精度地形；地球视觉真实感优先于地形细节。
- 用户未连接网络或影像资源加载失败时，使用随包提供的合法低分辨率纹理。

### 4.3 轨道与卫星动画

- 初始场景使用明确的任务初始轨道状态与轨道参数生成显示轨道。
- 黄色虚线轨道只表示轨道路径，不代表实时测量轨迹或真实轨迹误差。
- 默认地球自转、卫星公转仅作为主界面的场景时间动画；一旦创建仿真，场景时钟与仿真模式建立明确关系。
- 离线模式：场景可保持演示动画或静止展示，不将未执行的预测轨迹冒充仿真结果；结果曲线在右侧展示。
- 实时模式：卫星位置、姿态和可视状态必须来自当前 Basilisk 会话的真实遥测/状态采样。禁止单独使用前端 setInterval 按固定轨道“假装实时”。
- 数据采样间隔、延迟、缺口和插值策略必须可审计；短暂无新帧时可以平滑显示上一帧，但必须标记数据时间，不能补造新遥测。

### 4.4 模型节点选择与缩放

- 优先使用 glTF node/mesh 对应的模型节点 ID 做 pick。
- 选中节点后通过锚点变换获取世界坐标，镜头移动到对应局部区域。
- 如果单个部件没有独立 mesh，使用配置好的 fallback anchor 和名称标签；不把任意相邻网格误判成物理部件。
- 太阳翼展开、部件遮挡、模型层级和标签重叠要有明确处理策略。
- 任何空间选中动作都不应更改仿真配置；“选中”与“编辑参数”是两个独立状态。

## 5. 参数与参量命名规范

### 5.1 建立统一参量字典

新增产品级“单机—参量命名表”，作为参数卡片、指标卡片、曲线名称和自然语言输出的统一展示来源。每个条目至少包括：
- `parameter_id` / `telemetry_id`：稳定 ID；
- `object_id`：归属单机或对象；
- `display_name_zh`：中文显示名称；
- `quantity_name`：物理量名称；
- `unit`：SI 单位或明确工程单位；
- `description_zh`：简短物理含义；
- `source_field`：真实 Schema/Recorder 字段；
- `source_capability_id`：真实注册能力；
- `value_type` / `shape`：标量、向量、四元数等；
- `aggregation`：瞬时值、均值、最大值、末值等；
- `valid_range`：仅在源 Schema 提供时填写；
- `visibility_tier`：常用/专业/诊断；
- `provenance`：来源与版本。

### 5.2 显示命名规则

统一格式：`单机名称 + 参量名称`。例如：
- 反作用轮 1 · 角速度；
- 反作用轮 1 · 输出力矩；
- 星敏感器 1 · 姿态测量四元数；
- 三轴磁强计 · 磁场测量值；
- 蓄电池 · 荷电状态。

不允许只显示“最大速度”“控制力矩”等脱离对象的抽象名称。若字段归属于分系统而不是单机，使用“姿态控制分系统 · 姿态指向误差”等明确层级。

### 5.3 名称和字段映射治理

- 现有 `output_label()` 的 token 翻译只能作为回退，不再作为最终产品命名来源。
- 映射必须由人工审定或模型合同提供，禁止仅凭字符串前缀猜测物理归属。
- 一个物理量可能对应多个字段（例如 XYZ 分量、四元数），必须明确是一个复合量还是多个独立量。
- 同名不同单位、同单位不同参考系、同名不同执行后端必须区分。
- UI 显示中文名称，技术字段仅在“查看数据来源”中展开。
- 不存在真实 source field 的参量不得出现在可选曲线目录。

## 6. 结果面板与曲线布局

- 右侧面板默认展示当前选中对象的摘要和曲线；中央场景保持足够宽度。
- 曲线数量默认限制为 2–4 条，采用单列纵向紧凑图或可切换的小型多图；不再将所有指标卡平铺成密集网格。
- 用户选择新的对象时，结果面板按对象归属筛选字段；分系统可提供“本分系统汇总”和单机子对象切换。
- 跨分系统指标（例如能量守恒、任务成功状态）不应伪装成某个单机指标，应单独归入“整星综合”。
- 离线结果必须从已完成 Run Bundle/telemetry 读取；实时曲线必须来自实时会话真实遥测帧。
- 当前选中对象无数据时显示“该次运行未记录此对象的该参量”，不得用零值或模拟值占位。
- 结果面板隐藏“工程假设与适用范围”默认卡片。需要阅读模型边界时，放入独立“模型说明”帮助入口，不占用结果主视区。
- 移除“快捷操作调用现有图编辑器”“已复用旧页面”等开发说明；只保留用户可理解的操作名称。

## 7. 运行模式与后端能力矩阵

运行方式的可用性由后端 capability policy 决定。产品 UI 只负责把真实策略翻译成用户语言。

当前 `interactive/runtime_factory.py` 的批准集合为：
- 整星统一原生能力：支持限时实时与持续实时（部署策略另有限制）；
- ADCS 统一原生能力：支持限时实时（部署策略另有限制）；
- EPS 统一原生能力：支持限时实时（部署策略另有限制）；
- 通信数据统一原生能力：支持限时实时（部署策略另有限制）；
- 持续实时仅允许整星统一原生能力；
- 推进、热控、载荷、轨道环境以及大部分单机并未出现在当前交互批准集合中。

以上是源码策略快照，不是最终可用状态。每次会话创建仍须查询当前服务端能力目录。P9 必须增加真实联调验收，重点查清用户报告的“整星和姿态控制分系统均无法实时”：
1. 前端 `/health.features.interactive` 是否启用；
2. `/interactive/capabilities` 返回的模式和 creation 项；
3. 运行部署是否设置 `SAT_SIM_SUPERVISED_NATIVE_RUNTIME=1`；
4. capability ID 是否与前端选择一致；
5. 配置导入/预检是否失败；
6. 会话创建、prepare、start 和首帧遥测分别在哪一步失败。

不得通过删除策略、强行显示按钮或把分系统请求转成整星来“修复”。

## 8. 前后端数据契约

建议新增只读聚合接口，具体命名在实现阶段根据 API 版本规范确定：

### 8.1 场景目录

返回：
- 对象树与父子关系；
- 资产 URI、node/anchor 映射；
- 对象可选性、配置能力、实时能力；
- 可配置参数目录与参量目录；
- 每个字段的真实来源、单位、类型与可见层级。

场景接口不得复制第二套 Capability Registry。能力和参数仍来自当前 registry/schema，空间锚点只补充显示元数据。

### 8.2 实时场景状态

返回：
- session_id、真实 session state；
- sim_time_s、wall-clock receive timestamp、sequence；
- 当前对象位置、姿态（如该会话实际提供）；
- 遥测字段及其原始值；
- stream gap / freshness 状态；
- 当前运行模式。

状态快照与 WebSocket 增量帧必须使用同一字段语义和单位。未被当前会话记录的位置/姿态不得推断成真实实时状态。

### 8.3 离线结果查询

复用现有 Run Bundle、telemetry overview 和分页接口：
- run_id；
- selected object_id；
- 可用 telemetry 字段；
- 对应时间序列；
- 事件时间线；
- 验证状态。

不新建另一套仿真结果数据库。

## 9. 技术架构与模块边界

### 前端
- `scene/`：Cesium viewer 生命周期、地球、轨道、卫星、相机；
- `scene/assets/`：卫星模型与 anchor manifest；
- `scene/selection/`：对象树与场景选中同步；
- `scene/timeline/`：离线/实时场景时钟策略；
- `workspace/assistant/`：左侧任务流程；
- `workspace/object-panel/`：右侧配置/结果面板；
- `workspace/telemetry/`：对象过滤、指标卡和曲线；
- 现有 `app.js` 逐步拆分，不在一个超大脚本内继续堆叠三维 UI 业务。

### 后端
- 继续使用 `workbench_presentation_catalog`、Capability Registry、Schema、TaskSpec validator、Execution Planner、registered runners、Run Bundle 和 Interactive Session。
- 为场景元数据增加独立的 presentation/spatial manifest，不将视觉资产写进 TaskSpec。
- 实时状态适配层只读取真实会话状态和遥测；不拥有第二套仿真推进逻辑。
- 参量字典从注册输出和显式人工映射构建；不以猜测填充。

### V15 专业入口
- 独立菜单入口：“专业建模”。
- 进入 V15 后继续保留任务流程画布、多模块装配、模块拖拽、端口连接、节点检查器和导入导出。
- 新三维主界面不嵌入 V15 画布；V15 的参数面板和结果查看后续可复用命名字典，但不强制改变其专业操作模式。

## 10. 分阶段实施路线

### P9-A：数据与对象语义冻结

## 11. 关键验收旅程

1. 新用户打开首页：地球、卫星和黄色轨道在合理时间内加载，镜头跟踪卫星。
2. 选择“姿态控制分系统”：中央定位姿态控制相关区域，右侧显示姿态控制参数。
3. 选择“反作用轮 1”：中央定位轮体或其 fallback anchor，右侧显示轮速、力矩等该对象真实参数。
4. 修改一个参数：配置状态变为未校验；校验失败时明确指出字段和原因。
5. 运行离线仿真：场景不冒充实时结果；右侧展示反作用轮实际结果曲线。
6. 切换至星敏感器：右侧只显示星敏感器实际记录字段；没有数据时明确说明。
7. 选择姿态控制分系统并请求限时实时：必须由真实服务端能力目录允许；创建、启动、首帧遥测均成功。
8. 选择整星并请求持续实时：创建真实 Basilisk 会话，场景按真实状态更新；停止并归档后保留证据。
9. 断开实时连接：界面显示数据陈旧/连接中断，不继续伪造实时轨迹。
10. 进入“专业建模”：V15 原有画布、拖拽、端口连接和模块装配仍可使用。

## 12. 风险与防护

| 风险 | 防护 |
|---|---|
| 三维模型精细但没有真实节点映射 | 资产锚点清单、人工核验、fallback anchor |
| 实时场景只是前端动画 | 只消费真实 Basilisk 状态/遥测；数据时间可见 |
| 实时模式因策略被禁用 | 端到端检查 health、capability policy、create、prepare、start、first frame |
| 单机曲线归属错误 | 显式 telemetry ownership map，未知归属不显示为单机结果 |
| 参数中文名含义不准确 | 人工审定参量字典、单位/参考系校验 |
| 三维场景影响仿真性能 | 场景渲染与仿真 worker 隔离，帧率/内存基准 |
| 外部地球服务不可用 | 合法离线纹理与资源缓存 |
| 重构破坏专业用户流程 | V15 独立入口、旧流程回退开关、既有 E2E 回归 |

## 13. 设计冻结前需要用户确认的唯一关键语义

当前代码的“姿态与轨道控制”实际上把 ADCS 作为一个分系统名称，而“轨道与空间环境”又是单独对象。新产品需要将两者分开，但“轨道分系统”可能有不同物理含义：

- A. 轨道与空间环境：轨道传播、轨道状态、J2/阻力/光压等环境，不包含独立轨道控制执行机构；
- B. 轨道控制分系统：还包括轨道机动规划、推进控制、轨道保持等控制功能；
- C. 两者都要：轨道与空间环境作为基础对象，轨道控制作为独立功能对象，并明确其与推进分系统的关系。

在用户确认之前，界面设计按 A 建立独立“轨道与空间环境”对象，不把尚未注册的轨道控制能力作为已实现功能展示。
