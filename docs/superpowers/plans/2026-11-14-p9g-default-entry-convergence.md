# P9-G：默认入口收敛与专业建模保留

## 目标

在 P9-F 真实遥测驱动数字场景合并后，收敛工作台默认导航与用户入口：普通用户优先进入快速仿真流程；历史任务、运行结果和帮助能力保持容易发现；V15 专业建模作为独立、明确的高级入口完整保留。

本阶段是产品入口与导航信息架构调整，不改变仿真物理模型、Capability Registry、TaskSpec、Run Bundle、遥测协议或仿真执行状态机。

## 当前基线

- 默认导航已存在“开始仿真/卫星数字场景/专业建模/任务中心/实验中心/目标实验/运行中心/效能评估/系统诊断/运行日志”等入口。
- 快速仿真向导已承担普通用户的主要建模、配置、运行与结果查看路径。
- V15 专业建模仍由现有 creator / Visual Composer 能力承载，包含模块库、装配画布、检查器、编译、运行和程序包导出。
- P9-A 已明确：普通入口为“快速仿真”，V15 保留为独立“专业建模”入口。
- P9-F 已将真实 Basilisk 轨道遥测接入卫星数字场景；场景入口应与快速仿真、实时会话及封存 Run 结果保持一致。

## 设计原则

1. **默认路径唯一清晰**：首次进入工作台，视觉主入口是“开始仿真/快速仿真”，避免多个同等权重入口争夺注意力。
2. **专业能力不降级**：V15 专业建模保留独立入口、原有路由、模块库、装配、校验、运行和导出能力；不把专业建模强塞进普通向导。
3. **导航按用户任务组织**：把普通用户高频任务放在一级导航；低频运维与开发能力归入“高级工具”或任务中心二级区域，不删除原有功能。
4. **结果闭环可达**：历史记录、运行结果、实验与效能评估仍可从明确入口到达；不把“结果指标”混入仿真参数或仿真过程量。
5. **场景定位准确**：数字场景入口可从快速仿真结果、实时会话和运行中心到达；无真实轨道遥测时继续明确标识演示模式。
6. **状态连续性**：导航调整不得意外停止用户运行中的仿真、断开应保留的只读遥测订阅，或丢失当前 Run/TaskSpec 上下文。
7. **界面无开发痕迹**：默认用户视图不显示调试文案、内部模块名、测试说明或开发状态标签。

## 导航信息架构

### 一级主入口

- **快速仿真**：默认首页；选择对象、配置参数、执行仿真、查看结果均在引导流程中完成。
- **任务中心**：历史任务、运行记录、结果回看与任务状态；保留现有检索和恢复能力。
- **卫星数字场景**：全局地球、真实轨道位置、轨迹与对象选择；继续复用 P9-F 数据源。
- **专业建模**：V15 独立入口，明确标注“专业建模”，不与快速仿真混用术语。

### 二级/高级入口

- 实验中心、目标实验、效能评估归入任务/分析工作区的二级入口，保持原有 URL/view 与能力。
- 系统诊断、运行日志放入“高级工具”，默认不与普通仿真入口并列。
- 实时会话与持续卫星仿真仅在用户创建/恢复相应会话后显示或通过快速仿真/任务中心到达。
- 帮助与本地验收说明通过统一帮助入口访问；不在主导航堆叠技术文档链接。

## 实施批次

### P9-G1：导航梳理与路由基线
- 审计所有 data-view、快捷按钮、深链接和快捷键。
- 建立入口—视图—核心动作映射表。
- 记录 V15 专业建模入口与关键 DOM/API 合同，防止导航改造误伤。
- 明确哪些入口合并展示、哪些仅调整分组，不删除能力。

### P9-G2：默认首页与主导航收敛
- 首次加载落在快速仿真。
- 一级导航收敛为快速仿真、任务中心、卫星数字场景、专业建模。
- 高级工具和分析能力使用分组/二级入口，保持原功能可达。
- 为专业建模提供独立、清楚的说明和进入动作。

### P9-G3：跨入口状态与结果闭环
- 验证从快速仿真结果进入数字场景、任务中心和专业建模再返回时，当前任务上下文正确。
- 验证实时会话切换视图时不误停仿真。
- 验证封存 Run 的场景回放仍受成功、封存和完整性校验门禁控制。
- 验证刷新、浏览器后退/前进和直接深链接行为。

### P9-G4：产品级验收
- Chromium 验收首次进入、四个一级入口、二级功能可达性、帮助入口和响应式导航。
- V15 专项回归：模块库加载、模板装配、拖拽/连线、属性检查、校验、运行、结果查看和程序包导出。
- 回归 P7 对话框工作流、P8 本地验收、P9-A 对象树、P9-D 配置面板、P9-E Run 结果、P9-F 真实数字场景。
- 对比改造前后用户完成“创建一次仿真并查看结果”的步骤数与入口认知负担。

## 验收标准

1. 首次进入工作台明确落在快速仿真，不出现多入口同权重竞争。
2. 一级导航只保留四个主任务入口：快速仿真、任务中心、卫星数字场景、专业建模。
3. 原实验、目标实验、效能评估、诊断、日志等功能均可从合理的二级入口到达，功能与路由未删除。
4. V15 专业建模保持独立入口与原有能力，不被简化为只读预览或模板选择器。
5. 从快速仿真创建并完成 Run 后，可自然到达结果、历史记录和数字场景。
6. 活动实时会话在允许的导航切换中保持运行与遥测连续性。
7. 普通用户视图不出现调试语句或内部实现术语。
8. Chromium、前端单测、API 回归、Basilisk 原生回归通过。

## 不在本阶段范围

- 不重写 V15 专业建模器，不替换其图编辑器。
- 不改造 Basilisk 物理模型、遥测协议、TaskSpec 或 Run Bundle。
- 不把专业建模能力迁入快速仿真向导。
- 不删除实验、目标实验、效能评估、诊断和日志能力。
- 不在没有审定空间锚点的情况下扩展单机级三维资产。
