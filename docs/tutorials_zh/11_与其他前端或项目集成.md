# 11｜与其他前端或项目集成

## 本课目标

解释“我的另一个项目需要前端/仿真能力，怎么和 V15 打通”。

不要一开始复制 V15 的前端源码。优先把 SAT 当成一个**独立仿真后端/执行服务**。

---

# 1. 推荐的三种集成方式

## 方式 A：直接使用 V15 工作台

适合：

- 内部工程师；
- 仿真建模；
- 调试；
- 研究和验证。

你的其他项目只需要链接/打开 V15 工作台，不需要重复开发 Visual Composer。

这是成本最低的方式。

---

## 方式 B：其他系统调用导出的程序包

适合：

- Agent；
- 批处理平台；
- CI；
- 后台作业；
- 不需要网页编辑器的业务系统。

流程：

```text
V15 里把模型搭好
  ↓
导出可运行程序包
  ↓
其他系统调用 run_simulation.py
  ↓
读取 Run Bundle / stdout / artifacts
```

这是最容易稳定落地的集成方式。

---

## 方式 C：你的前端直接调用 SAT REST API

适合：

- 需要自定义业务 UI；
- 需要把仿真嵌到已有 Web 项目；
- 不想使用 V15 原生工作台界面。

SAT 启动后默认：

```text
http://127.0.0.1:8000
```

先测试：

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/capabilities
```

Visual Composer 相关 API 包括：

```text
GET  /visual-composer/assemblies
GET  /visual-composer/assemblies/{capability_id}
GET  /visual-composer/simulation-ports/{capability_id}
GET  /visual-composer/module-replacements/{capability_id}
GET  /visual-composer/module-library
POST /tasks/compile-graph
POST /tasks/compile-assembly
POST /tasks/export-script
POST /tasks/export-assembly-script
POST /tasks/export-program
POST /runs
POST /runs/{run_id}/execute-async
GET  /runs/{run_id}/execution
GET  /runs/{run_id}/metrics
GET  /runs/{run_id}/telemetry
```

# 2. 前端项目不要直接跨域硬连

如果你的 React/Vue/Next/Vite 开发服务器运行在另外一个端口，浏览器会涉及同源/CORS 问题。

V15 当前不建议依赖“所有来源都开放 CORS”。

更稳的方式是：

```text
浏览器
  ↓
你的前端 dev/prod server
  ↓ 反向代理 /sat-api/*
SAT :8000
```

例如开发环境让前端服务器把：

```text
/sat-api/health
```

代理到：

```text
http://127.0.0.1:8000/health
```

生产环境则让 Nginx/网关统一做同源路由。

---

# 3. 最小前端连通测试

前端只先实现健康检查，不要上来就重写整个 Visual Composer：

```javascript
const res = await fetch('/sat-api/health');
if (!res.ok) throw new Error('SAT backend unavailable');
const health = await res.json();
console.log(health);
```

然后再获取 Capability：

```javascript
const res = await fetch('/sat-api/capabilities');
const capabilities = await res.json();
console.log(capabilities);
```

当这两步稳定以后，再接任务编译/运行。

---

# 4. 推荐的业务集成层次

不要让业务前端理解所有 TaskSpec 细节。

推荐：

```text
业务前端
   ↓ 简化业务请求
你的业务后端 / BFF
   ↓ SAT API
SAT V15
   ↓
Run Bundle
```

BFF 负责把“用户业务输入”转换为平台需要的 Capability / TaskSpec / template 选择。

这样以后 V15 内部合同升级，不需要让所有页面跟着改。

---

# 5. 如果你的项目只是“需要一个仿真功能”

优先顺序：

```text
1. 导出程序包调用
2. 服务端 REST API 调用
3. 复用 V15 原生工作台
4. 最后才考虑复制/修改 V15 前端源码
```

通常不要直接 fork 前端然后把所有 SAT 内部状态管理搬进业务项目。
