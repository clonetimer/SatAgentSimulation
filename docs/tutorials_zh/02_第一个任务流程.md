# 02｜第一个任务流程

## 本课目标

学习“任务流程”模式。它比多模块装配简单，适合先理解：

```text
一个 Capability
  → 参数
  → TaskSpec
  → Python
  → Run
```

---

# 1. 进入任务流程

打开：

```text
图形组装 → 任务流程
```

左侧可以搜索平台已注册的 Capability。

第一次建议选择一个简单部件，例如：

```text
component.reaction_wheel.v1
```

如果当前环境中该 Capability 没出现在列表，可以选择任意界面显示为可执行的部件/分系统 Capability。

---

# 2. 拖到画布

把 Capability 从左侧拖到画布。

然后使用：

```text
恢复基础流程
```

或：

```text
自动布线
```

典型流程会形成：

```text
模型
 ↓
参数配置
 ↓
事件注入
 ↓
输出选择
 ↓
Python 代码
 ↓
运行器
```

---

# 3. 点击节点看右侧属性

点击不同节点，观察右侧检查器。

第一次不要同时修改很多参数。

建议只修改一个容易理解的运行参数，例如：

```text
duration_s
```

修改以后，你应该看到当前模型被标记为需要重新编译/生成。

---

# 4. 校验图

点击：

```text
校验图
```

如果通过，说明：

- 图结构合法；
- Capability 一致；
- 类型化连接合法；
- 能编译为 Canonical TaskSpec。

如果失败，不要直接改 JSON，优先看画布错误提示。

---

# 5. 生成 Python

点击：

```text
生成 Python
```

右侧/代码区域会出现平台生成的确定性 Python。

这里最重要的认识是：

> 图形编辑器不是把节点名字随便拼成 Python；它先生成标准 TaskSpec，再由平台 exporter 生成代码。

所以生成代码是受注册执行边界保护的。

---

# 6. 只移动节点会不会让代码失效？

不会。

V15 中：

- 移动节点；
- 自动布局；
- 左对齐；
- 顶对齐；
- 等间距；

只改变画布坐标，不改变 TaskSpec。

真正会让代码变旧的是：

- 改参数；
- 改 Capability；
- 改物理连接；
- 改模块选择。

---

# 7. 构建并运行

点击：

```text
构建并运行
```

完成后进入：

```text
查看运行结果
```

---

# 8. 保存任务流程工程

你可以：

- 保存浏览器草稿；
- 加载浏览器草稿；
- 导出 `.satgraph.json`；
- 再导入 `.satgraph.json`。

推荐：重要模型不要只依赖浏览器草稿，额外导出 `.satgraph.json` 保存进 Git 或工程资料目录。
