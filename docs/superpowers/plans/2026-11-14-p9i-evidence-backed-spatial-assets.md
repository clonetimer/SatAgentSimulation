# P9-I：有证据约束的单机三维资产与安装锚点

## 目标

在 P9-H 已完成真实轨道与姿态驱动的基础上，建立从“对象树中的设备类别”到“真实装机实例三维节点”的可审计映射。只展示有资产来源、实例身份、坐标系和安装依据的几何；不得把仿真能力目录中的类别数量解释为整星实际装机数量。

本阶段不是给现有示意卫星继续增加装饰模型，而是建立可持续接入型号 CAD/装配数据的空间资产体系。

## 当前仓库审计结论（main：6bf0ff7）

### 1. 对象树已经明确区分类别与装机实例

- `workbench_scene_catalog.py` 将组件类别转换为对象节点，并为全部类别生成 `spatial_anchor: None`。
- `workbench_object_tree.py` 对设备类别使用 `instance_semantics=capability_model_not_vehicle_inventory`、`inventory_count=None`。
- 树的语义显式声明 `spatial_anchors_require_asset_evidence=True`。
- 外部设施、任务逻辑量和链路关系被放在卫星硬件树之外，不应作为星内实体装配。

因此，当前对象树表达的是“模型/能力类别”，不是某一具体型号的 as-built 设备清单。

### 2. 当前三维本体是程序生成的示意模型

- `satellite-scene.js::makeSatelliteModel()` 使用 Three.js 基础几何创建长方体星体、太阳翼、铰链、锥形天线和坐标轴。
- 代码明确声明其局部轴向是 visualization convention，不是 CAD/as-built mounting。
- 未发现受控 GLB/GLTF 模型资产注册表、型号装配资产清单或已审定的单机安装变换。
- 现有反作用轮 per-wheel 位置/轴向参数属于物理仿真模型中的 B 系安装几何输入；不能未经型号装配数据核对就直接视为真实 CAD 锚点。

### 3. P9-I 的第一原则

`spatial_anchor=None` 是有效且正确的状态，不是需要用默认坐标填满的缺陷。没有来源证据的对象保持在对象树中，但不生成三维装机节点。

## P9-I 数据契约

### A. 资产登记（Model Asset Registry）

每个模型资产至少登记：

- `asset_id`、`asset_version`、`asset_format`（优先 glTF/GLB）。
- 仓库内受控相对路径；禁止任意外部 URL 和运行时远程模型加载。
- SHA-256、文件大小、来源文档/图纸标识及其版本。
- 授权/使用范围、审核状态、审核记录。
- 长度单位、模型上方向、前向轴、原点语义、局部坐标系定义。
- 几何包围盒与显示 LOD；模型原点不得默认为质心或安装基准。

资产只有在哈希、路径、格式、单位、坐标系和来源审核全部通过后才可进入可渲染清单。

### B. 装机实例（As-built Equipment Instance）

装机实例必须独立于能力类别：

- `instance_id`：具体装机实例标识；不能由类别名自动推导或虚构数量。
- `object_id`：关联对象树中的设备类别。
- `asset_ref`：受控资产 ID + 版本 + SHA-256。
- `parent_instance_id`：所属舱板/支架/结构件实例。
- `mount_frame_id`：安装基准坐标系。
- `T_parent_mount`：父安装基准到设备模型原点的刚体变换。
- 平移单位固定为 m；旋转使用 scalar-first Hamilton 四元数；矩阵约定、主动/被动语义必须显式标注。
- `source_evidence`：CAD 装配、机械接口控制文件、安装图或经审核的型号配置来源。
- `verification_status`：draft / reviewed / verified / rejected；只有 verified 可进入真实装配场景。

### C. 坐标链

装配显示必须有完整的坐标链：

`N (Basilisk inertial) → B (spacecraft body) → spacecraft datum → panel/bracket datum → equipment mounting datum → asset local frame`

P9-H 的真实姿态负责 `N ↔ B`；P9-I 只负责有证据的刚体安装变换和资产局部坐标，不重复实现姿态或轨道计算。

坐标变换必须使用统一的 SE(3) 组合规则；禁止把 Euler 角字段直接拼接、混用毫米/米或将图纸视图坐标误作装配坐标。

## 分阶段实施

### P9-I0：只读资产与锚点盘点（本批）

1. 冻结上述仓库审计结论。
2. 统计对象类别、外部/逻辑/关系节点、现有空间锚点和真实模型资产。
3. 建立资产与安装证据准入清单。
4. 形成负向验收：无资产、无实例 ID、无坐标系、无安装来源的节点不得被渲染为真实硬件。
5. 保留现有示意卫星，并始终显示“示意模型”标识。

### P9-I1：契约与验证器

1. 增加版本化 asset manifest 与 equipment-instance schema。
2. 校验路径穿越、哈希不符、未审核资产、单位缺失、坐标系缺失、非单位四元数、重复 instance ID、父子循环。
3. 校验每个设备实例只引用一个明确的资产版本和一个安装来源。
4. 不要求仓库中先有型号 CAD；没有资产时注册表为空，验证器应正常通过空集并保持无装机节点。

### P9-I2：首个真实装配样例

1. 仅选择来源资料完整、安装基准明确的一个单机及其父结构作为试点。
2. 由来源资料建立实例 ID、父子关系和 B/安装坐标变换。
3. 使用独立坐标基向量测试验证安装方向，使用实测/图纸尺寸核对比例。
4. 资产加载失败、来源被撤销或哈希变化时 fail closed，不显示上次缓存模型冒充当前资产。

### P9-I3：场景装配渲染

1. 复用现有 Globe.gl/Three.js 场景生命周期和 P9-H 姿态链。
2. 将受控 GLB/GLTF 资产加载到经验证的实例树，不改变 Basilisk 仿真状态。
3. 对象树选择、模型高亮、检查器和历史 Run 使用同一 instance ID。
4. 相机、轴向、缩放和移动端可读性验收；无锚点对象只展示“未建立装配位置”，不伪造位置。

### P9-I4：扩展与回归

1. 按真实装配证据逐类扩展，不按对象树类别数量批量生成占位模型。
2. 核验太阳翼、天线、反作用轮、传感器等模型局部坐标与物理参数的对应关系。
3. 复跑 P9-C 至 P9-H：场景生命周期、对象配置、Run 关联、实时/历史轨道与姿态、原生整星回归。

## 验收门禁

- **来源可追溯：** 每个真实几何节点都能追溯到资产哈希和安装证据。
- **实例真实：** instance ID 与 as-built 装机清单一致；类别数不替代实例数。
- **坐标正确：** 单位、原点、轴向、旋转约定及父子变换均通过独立基向量测试。
- **物理解耦：** P9-I 只消费只读仿真状态，不改动 Basilisk 动力学或控制执行。
- **失效安全：** 缺来源、哈希错误、非法变换或未审核时不渲染真实硬件。
- **用户可理解：** 区分真实资产、示意模型和未定位对象；不使用开发调试语句。
- **回归通过：** 所有受影响平台测试及 P9-C～P9-H 回归通过后才合并。

## 本批明确不做

- 不臆造卫星型号、设备数量、设备安装坐标或 CAD 尺寸。
- 不把 RW 仿真中的安装位置参数自动升级为 as-built 安装锚点。
- 不用随机/规则化摆放替代装配关系。
- 不把外部地面站、链路预算、数据队列等逻辑对象渲染为星内硬件。
- 不移除当前示意模型；在真实资产验收完成前保留其明确标识。
