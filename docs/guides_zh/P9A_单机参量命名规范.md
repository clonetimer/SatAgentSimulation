# P9-A：单机—参量命名规范与对象树

## 1. 命名原则

普通用户看到的参数、指标和曲线统一使用：

**单机名称 · 参量名称**

示例：

| 单机对象 | 用户显示名称 | 单位 | 实际来源字段 |
|---|---|---|---|
| 反作用轮组 | 反作用轮组 · 逐轮转动惯量 | kg·m² | wheel_inertia_kg_m2 |
| 反作用轮 1 | 反作用轮1 · 角速度 | rad/s | adcs.reaction_wheel.speed_rad_s_0 |
| 反作用轮 1 | 反作用轮1 · 实际电机力矩 | N·m | adcs.reaction_wheel.applied_torque_nm_0 |
| 蓄电池 | 蓄电池 · 荷电状态 | 0–1 | eps.battery.soc |
| 星敏感器 | 星敏感器 · 姿态误差参数 X 分量 | MRP | adcs.star_tracker.sigma_x |
| 磁力矩器 | 磁力矩器 · 输出力矩 X 分量 | N·m | adcs.mtb.torque_nm_0 |
| 太阳电池阵 | 太阳电池阵 · 总输出功率 | W | eps.solar.array_power_w |

设备索引与坐标分量必须区分。反作用轮遥测字段后缀 _0 表示当前模型合同中的 1 号轮；MTB 等矢量字段后缀 _0/_1/_2 表示 X/Y/Z 分量，不能统一按设备编号解释。

## 2. 对象树

产品对象树采用：

整星 → 分系统 → 单机 → 输出参量 / 物理参数

- 姿态控制分系统独立于轨道与空间环境。
- 轨道控制是独立功能对象，与推进分系统通过控制命令和执行反馈关联。
- 轨道与空间环境提供轨道状态、轨道传播和环境摄动。
- 地面站、链路预算、数据队列、功率负载和热节点属于外部/逻辑对象，不作为卫星实装单机。
- 24 项组件合同表示当前可配置的模型类别，不代表真实整星硬件安装数量。没有型号 BOM、装配清单或实装实例证据时，不生成“1号/2号/3号”设备清单。

## 3. 字典范围

当前字典包含 24 个组件模型类别，共 389 条审定映射：

| 类型 | 条目数 |
|---|---:|
| 物理参数 | 150 |
| 时序输出参量 | 169 |
| 结果摘要指标 | 70 |
| 合计 | 354 |

字典按姿态控制、能源/热控、通信/载荷/推进三个文件组织：

- src/sat_sim/workbench_quantity_dictionary_adcs.json
- src/sat_sim/workbench_quantity_dictionary_eps_thermal.json
- src/sat_sim/workbench_quantity_dictionary_comm_payload_propulsion.json

src/sat_sim/workbench_quantity_names.py 提供查询、来源绑定和单位/dtype 校验。每个组件条目记录对应 Capability YAML 的 Git blob，避免源字段变化后继续沿用过期名称。

## 4. 数据治理规则

1. Capability Registry 和实际 Recorder 输出是参数与遥测的来源；字典只负责产品显示名称和归属。
2. 参数名称必须匹配真实 Schema 字段，单位必须一致。
3. 曲线名称必须匹配真实输出字段、能力合同、单位和数据类型。
4. 未审定字段不通过字符串拆词猜名，不进入普通用户指标与曲线列表；必须先补充字典、审查源字段，再开放展示。
5. 未记录的参量显示“本次运行未记录”，不得用零值或模拟值填充。
6. 对象树中的组件节点表示模型对象，不代表真实卫星设备实例数量；只有来源明确提供的设备索引才显示编号。
7. Run Bundle 中的 provenance、工程边界和验证证据继续保存。它们不再作为默认结果卡片占据主界面。

## 5. 后续扩展

本轮先完成 24 个单机组件模型的首批命名和对象树。后续继续补齐整星、分系统层级的综合参量，以及型号级真实装配实例、空间锚点和 GLB 节点映射。每一项新增名称都必须有源字段、单位、物理含义和适用对象，不以界面文案推断物理模型能力。
