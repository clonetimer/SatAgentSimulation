# Calibration Profile Guide

## Recommended process

1. Select a profile target: `engineering_estimate`, `ground_calibrated`, or
   `flight_correlated`.
2. Copy `configs/parameters/demo_parameter_registry_v1.json` to a new profile
   file.
3. Replace demo records with traceable evidence:
   - source document or dataset ID;
   - immutable SHA-256 checksum for datasets;
   - unit and operating range;
   - uncertainty model and correlations;
   - calibration method and validation residual.
4. Register datasets in `data/calibration/manifest_v1.json`.
5. Run `scripts/check_parameter_provenance_calibration_1.py` and profile-specific
   validation scripts.

## Subsystem calibration priorities

| Subsystem | First calibration target | Reason |
|---|---|---|
| ADCS | inertia, RW/CMG torque/friction, sensor scale/bias | Dominates pointing and payload enable gate |
| Comm/Data | EIRP, G/T, bandwidth, CNR/EbN0-to-PER curve | Dominates delivered vs dropped data |
| EPS | battery capacity, solar generation, mode loads | Dominates energy feasibility |
| Thermal | heat capacity, conductance, heater power | Dominates thermal safety margin |
| Propulsion | thrust, Isp, min impulse bit, leak rate | Dominates maneuver/fault claims |

## Dataset manifest expectation

Each ground or flight dataset should include:

```json
{
  "dataset_id": "rw_SN003_coastdown_2026Q3",
  "path": "data/calibration/rw_SN003_coastdown.parquet",
  "sha256": "...",
  "subsystem": "adcs",
  "equipment_model": "...",
  "serial_number": "...",
  "operating_range": {
    "temperature_c": [15, 35],
    "speed_rad_s": [0, 800]
  },
  "validation_split": "holdout_20_percent",
  "residual_metric": "RMSE",
  "approval_status": "approved"
}
```

## Profile failure is intentional

If a profile requests `engineering_estimate` while using the demo registry, the
parameter gate should fail.  This protects reports from overstating fidelity.
