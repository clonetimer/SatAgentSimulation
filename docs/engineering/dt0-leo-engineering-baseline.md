# DT-0 首期 LEO-Engineering 基线与验收方案

**日期：** 2026-11-20  
**状态：** 首期基线候选；DT-0 审核后冻结  
**主线：** 一颗 LEO 卫星的轨道—姿态—环境—器件—数字场景联合仿真

## 1. 目标与边界

首期不同时铺开 GEO、深空、百星星座和 HIL。先建立一颗 LEO 卫星的可复现、可验证、可观察的整星闭环。

本基线区分两个版本：

- **LEO-Engineering-R0（现状基线）：** 如实记录 main 当前推荐整星模型已经具备的物理能力和缺口；可以运行，但不得宣传为完整高保真。
- **LEO-Engineering-R1（目标基线）：** 在 R0 上补齐首期 LEO 所需的重力阶次、大气阻力、SRP、环境/器件非理想及独立 V&V，并完成同一 Basilisk 整星图和数字场景联动。

R0 是工程现状，不是 R1 的验收替代品。

## 3. R1 目标物理范围

### 3.1 LEO-Engineering 必需能力

1. 地球重力：至少 J2–J4，系数文件、归一化、参考半径和坐标约定明确。
2. 大气阻力：NRLMSISE-00，输入 F10.7/Ap 或明确版本化空间天气数据。
3. 太阳光压：真实太阳星历、日食/阴影、面积与反射系数；先验证 Cannonball，再按任务需求扩展表面模型。
4. 第三体：DE430 Sun/Moon。
5. 环境：WMM/IGRF 模型显式可选；太阳/地球历元、时间尺度和参考系一致。
6. 姿态：刚体动力学、控制器、反作用轮和实际执行机构输出。
7. 传感器：IMU、星敏、磁强计、太阳敏感器的安装、噪声、偏置、漂移和有效性状态按真实模型实现。
8. 数据：全链路质量、来源、时间、单位、随机种子和模型版本可追溯。
9. 场景：整星、分系统、单机与轨道位置、姿态、安装关系和真实遥测对应。

### 3.2 精密轨道扩展

固体潮、海潮、更高阶重力、精细地球定向参数和相关环境产品进入 LEO-Precision，而不是不加区分地默认开启在所有 LEO-Engineering 任务中。

是否启用由任务精度要求和误差预算决定；不得将“模型可选”宣传成“所有任务都必须运行”。

## 5. 误差预算与数值验收原则

当前没有足够任务信息为所有轨道/姿态输出设置一个统一米级或角秒级容差。R1 的数值门槛必须先由目标任务决定，再写入版本化验证配置。

每个基准用例至少记录：

- 任务目标和有效时间弧；
- 参考系、时间尺度、历元、地球常数和重力场；
- 力模型开关、模型版本、系数/星历资产 SHA-256；
- 积分器、积分步长、输出采样间隔；
- 位置/速度 RTN 残差、轨道根数残差；
- 姿态角误差、角速度误差；
- 力模型分项贡献；
- 随机模型的 seed、样本数、统计置信区间；
- 对比工具/参考解版本及其配置；
- 不确定度来源和最终误差预算。

数值收敛至少比较 h、h/2、h/4；按所用积分器的理论阶次检查误差趋势。最终容差由任务需求和独立参考共同确定，不能为了通过测试事后放宽。

STK/GMAT 交叉比对必须确保同一力模型、参考系、时间系统、地球常数、重力系数、空间天气输入和积分设置。模型不一致时只能作为差异分析，不能直接把轨迹差异归因于本项目模型误差。

## 6. 置信度和结果标签

建议逐项标注，而不是给整个平台一个统一等级：

- D0：演示/简化或代理数据；
- D1：真实后端执行烟测；
- D2：内部物理基准和回归通过；
- D3：独立工具/参考数据交叉验证；
- D4：任务级容差和误差预算通过；
- D5：地面硬件/飞行数据相关性验证（仅在确有对应数据时）。

上述 D0–D5 是本计划提出的产品标签草案，尚未替代现有 TaskSpec assurance 或发布等级。DT-0 后续需评审后再纳入正式 Schema。

## 7. 首期阶段出口

LEO-Engineering-R1 不以“模块存在”作为退出条件。必须同时满足：

1. 目标物理模型在推荐整星执行图中真实运行；
2. 关键模型具有独立物理验证；
3. 数值收敛和任务容差有数据；
4. 真实故障/非理想输入能产生可观测物理响应；
5. Run Bundle 保存足够的版本、资产、种子和环境证据；
6. 数字场景显示同一仿真对象、真实安装映射和真实数据来源；
7. 历史 Run 能够复现同一输入和结果；
8. 未完成的模型和未验证的输出仍显式标注。
