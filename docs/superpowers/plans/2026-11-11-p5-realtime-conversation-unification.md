# P5：限时实时与持续实时对话式一致化

## 目标

让用户从同一个对话式工作区进入两类实时仿真，使用一致的任务选择、会话创建说明、状态观察和返回路径；保留两类会话各自真实的后端能力、状态机、遥测链路与安全门禁。

本阶段统一的是交互层级和信息架构，不是把限时实时与持续实时合并成同一种执行协议。

## 现有实现审计

### 限时/可暂停实时会话

- 入口：`interactiveView`，由 `switchView('interactive')` 管理。
- 会话 API：`/interactive/capabilities`、`/interactive/sessions`、`/interactive/commands/catalog`。
- 现有控制器：`createInteractiveSession()`、`interactiveControl()`、`sendInteractiveCommand()`。
- 实时遥测：WebSocket 帧、stream catalog、gap 记录、事件与 command acknowledgements。
- 已有操作：创建、启动、暂停、继续、单步、调整倍速、停止并归档、遥控和回执。

### 持续实时会话

- 入口：`continuousView`，由 `SatContinuousConsole.enter()/exit()` 管理。
- 控制器位于 `src/sat_sim/web/continuous.js`，拥有独立的创建、状态刷新、控制、遥控、遥测、资源监测、长稳证据和恢复覆盖审计。
- 已有操作：创建、启动、暂停、继续、单步、停止并归档、倍速、遥控、证据采集、资源监测和恢复审计。
- 自动恢复保持关闭；不自动重放遥控；父进程/原生执行异常不伪装成可恢复。

### 当前体验问题

- 两类实时工作区拥有不同的创建表单、状态区和控制布局。
- 限时实时创建表单与遥控区仍有较多字段，持续实时还有工程级原生配置、资源监测、恢复审计和长稳证据区。
- 向导已能分别进入两类实时会话，但尚未形成统一的“选择会话类型 → 创建/选择会话 → 控制与观测 → 归档/返回”交互层级。
- 两套后端 API 与状态机不可简单合并；持续实时的长稳/恢复工具也不适合压缩成普通聊天气泡。

## 交互方案

### P5-A：统一实时入口与会话概览

- 在向导“运行方式”步骤中，明确区分“限时实时”和“持续实时”，解释适用方式、运行结束条件和主要能力差异。
- 运行方式的可用状态由服务端 policy 决定；不可用时展示真实原因，不提供可点击的伪入口。
- 进入实时工作区后，先展示会话状态摘要与当前会话选择；创建表单作为可展开的“新建会话”步骤，不与运行控制区同时争夺视觉焦点。
- 历史会话、当前会话、归档会话明确区分。

### P5-B：统一控制操作层级

- 两类工作区使用一致的主操作顺序：启动 → 暂停/继续 → 单步 → 停止并归档。
- 根据各自真实状态和服务端允许操作动态启用/禁用按钮；状态未知时不允许发出危险指令。
- 限时实时与持续实时保留各自控制函数与 endpoint；不新增通用伪 API。
- 停止和归档提供二次确认；已终态会话不展示可执行控制按钮。
- 控制请求中明确显示提交中与服务端回执；不将请求已发送误写为仿真已完成。

### P5-C：统一遥测、事件与指令反馈的信息层级

- 顶部统一展示：会话 ID、真实状态、仿真时间、墙钟/倍速（若该模式提供）、连接/遥测新鲜度。
- 中部默认展示遥测趋势和最新值；按分系统/观测目的选择流和字段。
- 事件时间线与遥控回执分区展示，区分已提交、已确认、已拒绝、执行失败和遥测缺口。
- 保留各模式已有 stream catalog、采样率、缺口统计和真实数据来源。

### P5-D：高级运维能力渐进披露

- 持续实时的原生参数、真实资源监测、长稳证据采集、恢复覆盖审计保留为“工程与诊断”折叠区，不放进普通控制主流程。
- 限时实时的原生能力门禁、离线配置导入审核和诊断详情按需展开。
- 不支持的能力明确显示服务端 policy 原因；不把限时实时的能力冒充为持续实时能力，反之亦然。

### P5-E：安全离开与恢复

- 活动会话离开控制台前继续执行确认提示；离开不自动停止服务端仿真。
- 返回向导后显示活动会话仍在运行的明确提示和重新进入入口。
- 重新连接只使用现有 session selection / server refresh / websocket protocol。
- 不自动恢复原生计算图、不重放 TC、不补造缺失 TM；恢复审计只报告证据，不改变运行状态。

## 已完成的第一批工作

### P5-A：运行方式说明与控制器边界冻结

- 向导运行方式卡片已明确说明三种模式的运行结束条件与用途。
- 限时实时说明按时长结束，支持暂停/继续/单步与实时遥控。
- 持续实时说明由用户主动停止并归档，突出长时间遥测、资源监测和长稳证据用途。
- 模式可用性仍由现有服务端 policy 决定；未支持时展示原因，不绕过门禁。
- 新增 `tests/test_p5_realtime_conversation_contracts.py`，确认两类实时模式继续使用各自控制器、API 与安全边界。
- 本轮 unit tests 已通过；浏览器 smoke、Agent 和有限仿真回归仍在最新提交上运行。


### P5-B：当前会话概览统一（第一批已完成）

- 限时实时与持续实时工作区均新增同样结构的“当前会话”摘要卡，显示会话 ID、模式、真实状态、仿真时间和倍速。
- 两种模式的会话列表均将当前选中会话置顶，其余会话保持服务端原有顺序，便于从多条历史记录中识别当前控制对象。
- 当前会话未选择时明确提示从列表选择或创建新会话。
- 会话错误/归档错误保留在摘要辅助信息中，不伪造成功状态。
- 摘要由各自已有的 session snapshot 驱动；不新增 API，不合并状态机。
- 新增静态契约测试，检查两个模式的摘要节点、状态驱动渲染和共用样式。

## 实施顺序

1. 先完成两种模式的能力差异矩阵与服务端 policy 映射。
2. 统一向导运行方式说明和进入路径。
3. 收敛限时实时会话列表/创建表单的视觉层级。
4. 收敛持续实时的会话创建/控制主区；将资源监测、长稳证据和恢复审计归入工程折叠区。
5. 统一会话摘要、状态徽标、控制按钮顺序、遥测新鲜度和回执展示。
6. 完成真实 Chromium 两模式回归与原生会话生命周期测试。


### P5-C：控制操作标签与视觉层级统一（第一批已完成）

- 限时实时和持续实时统一显示“启动、暂停、继续、单步、停止并归档”五个动作名称。
- 两种模式使用相同的控制按钮尺寸、基础样式与窄屏换行策略。
- 按钮 enable/disable 仍由各自服务端状态驱动；限时实时仍调用 `interactiveControl()`，持续实时仍调用 `SatContinuousConsole.control()`。
- 停止/归档二次确认和服务端状态回执保持原实现。
- 新增静态契约测试，检查两种模式五个动作的可见标签及原控制 action 属性。

## 验收

- 限时实时与持续实时分别从向导进入，创建和选择会话成功。
- 启动、暂停、继续、单步、停止/归档均调用原有正确 API，状态变化由服务端回执驱动。
- 两种模式的遥测、事件、遥控回执和连接状态来源准确。
- 不支持能力按服务端 policy 解释；不出现伪造能力、假进度、假遥测。
- 活动会话离开提示有效；离开不自动停止；重新进入不重放遥控。
- 原生 Basilisk、会话生命周期、资源保护、长稳证据和恢复审计测试通过。


## 用户体验重构原则（本阶段新增）

本阶段以用户任务闭环为验收对象，不以样式统一作为完成标准。完整用户旅程、信息架构、最终验收场景见 `docs/superpowers/plans/2026-11-11-p5-user-experience-reframe.md`。

### P5-UX1：创建流程渐进披露（已实现第一批）
- 限时/持续实时创建表单均改为可折叠；首次且无会话时展开，选择/创建会话后收起。
- 高级原生参数仍单独可展开；不删除参数、不更改创建 payload 或服务端 policy。
- 静态契约测试覆盖首次进入与活动会话的披露规则。

### P5-UX2：遥测物理含义可读（已实现第一批）
- 常见轨道、姿态、飞轮、能源与通信字段显示中文物理含义和单位。
- 原始字段名保留在 title/技术信息中；未登记字段保持原名，不猜测其物理意义。
- 事件/遥控状态的用户文案正在逐步扩展；本批先覆盖限时实时 ACK 与会话事件。


### P5-UX2 / P5-UX3：数据新鲜度与事件/指令反馈（第一批已完成）

- 限时实时按遥测流记录实际收到帧的本地时间，并显示最近接收时刻；未收到帧时显示明确空状态。
- 持续实时和限时实时均把常见遥控 ACK 状态转换为用户可读文案；未知状态仍显示原始值。
- 持续实时事件显示可读状态迁移；reason code、仿真时刻、sequence 等技术证据继续保留。
- 新增静态契约测试，验证接收时刻来自真实帧到达回调、事件/ACK 状态说明及 reason code 保留。

### P5-UX5：离开后重新进入（第一批已完成）

- 从限时/持续实时返回向导后，若当前浏览器仍有已选会话，向导提供直接返回入口，并展示会话 ID 与状态。
- 持续实时控制器只暴露只读的当前选择 ID；重入仍调用原控制台刷新逻辑。
- 不创建新会话、不自动启动、不自动恢复原生计算图、不重放 TC。

### P5-UX2：关键卫星状态概览（第一批已完成）

- 限时实时在曲线前新增关键状态卡，优先呈现轨道、姿态、能源三类指标。
- 指标必须存在于当前遥测帧才显示；当前流不提供时给出切换遥测流提示，不显示默认值或合成评分。
- 连续实时沿用已有轨道半径、姿态指向误差、电池 SOC 真实值卡片。

### P5-UX5：跨页面重新进入与操作防重（第一批已完成）

- 重新进入限时实时时优先恢复浏览器当前会话；新页面/刷新后无本地选择时，优先选择服务端返回的非终态会话。
- 持续实时同样优先选择非终态会话；重新进入仅刷新服务端状态与遥测，不创建新会话。
- 两套控制器增加 pending guard，防止重复点击造成重复控制请求；遥控提交也显示提交中状态。
- 控制提示使用“请求已提交”措辞，最终状态仍由服务端状态刷新和 TC ACK 决定。
