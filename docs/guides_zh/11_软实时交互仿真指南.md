# 软实时交互仿真指南

## 能力边界

交互模块提供内部工程仿真的常驻会话、暂停/继续、单步、七档倍速、受控遥控、实时遥测、断线续读和终态证据封存。它是软实时系统，不提供硬实时、硬件在环、真实星上协议或飞行验证声明。

该功能默认关闭。启用前设置：

```bash
export SAT_SIM_INTERACTIVE_ENABLED=1
```

生产或共享环境还应启用 Token 认证，并配置 `viewer`、`operator`、`fault_operator`、`admin` 角色。不要在 URL query 中传递长期凭据。

## 工作台操作

启用后，工作台显示“实时会话”导航。基本顺序为：

1. 默认创建“整星”会话；姿轨控、能源和通信数传共享同一仿真时钟与整星状态。只有专项调试时才从“高级：分系统独立调试”选择单分系统会话。
2. 启动后观察连接状态、会话状态、仿真时间、漂移和多速率曲线。
3. 暂停后可按 1、5 或 10 个 quantum 单步；恢复或切换倍速只在 quantum 边界生效。
4. 整星会话的“控制对象”按整星、姿轨控、能源和通信数传分层选择；同一会话可以依次向不同分系统发送遥控，不需要创建多个孤立会话。
5. 遥测按整星概览、轨道与环境、姿轨控、能源、热控、有效载荷、通信数传和推进分类查看；这些数据均来自同一次整星推进。
6. 遥控先形成确定性命令信封。自然语言只能生成候选，必须通过目录校验并由人确认。
7. 故障/退化命令要求 `fault_operator` 或 `admin`，停止和危险操作需要二次确认。
8. 正常完成后检查 ACK 时间线、效果窗口、ValidationOutcome、ClaimReport 和密封 Run Bundle。最后一条指令 ACK 后至少保留一个遥测 quantum，再停止归档，以形成完整的指令效果窗口。

## API

REST 根路径为 `/interactive/sessions`。控制统一发送到：

```text
POST /interactive/sessions/{session_id}/control
```

请求体的 `action` 为 `start`、`pause`、`resume`、`step`、`rate`、`stop`、`abort` 或 `heartbeat`。遥控入口为：

```text
POST /interactive/sessions/{session_id}/commands
```

WebSocket 遥测入口为：

```text
WS /interactive/sessions/{session_id}/telemetry
```

客户端首先发送 `subscribe`，声明白名单 stream、可选 `after_sequences`、容量和背压策略。窗口外续读返回显式 gap；慢客户端采用 `drop_oldest` 或断开，不能阻塞仿真线程。

## 安全与限额

- 未注册 operation、未知字段、越界参数、路径、任意代码和 shell 请求均拒绝。
- 同一 `command_id` 的同内容重放幂等；不同内容冲突拒绝。
- 命令要求匹配 session、revision 和角色；HTTP 命令与 WebSocket 消息均限制为每主体/会话每秒 20 条。
- WebSocket 单消息不超过 65,536 字节，并受认证、Origin、心跳和空闲超时约束。
- 遥测只能读取 Capability 冻结字段白名单，不能临时访问模型内部属性。
- 指令、状态和遥测工作区采用追加式哈希链；篡改后恢复和封存 fail-closed。

## 性能复验

CI 短测用于发现回归，但不能关闭正式时长门：

```bash
python scripts/run_interactive_performance_benchmark.py --profile ci
```

正式门会真实执行 1x 墙钟 30 分钟和单会话 4 小时仿真，不使用短测外推：

```bash
python scripts/run_interactive_performance_benchmark.py --profile formal
python scripts/run_interactive_assurance_acceptance.py --matrix all
```

机器可读结果位于 `reports/interactive/performance_benchmark.json`、`security_acceptance.json` 和 `reliability_acceptance.json`。性能预算以 `configs/interactive/performance_budget.json` 为准。

当前 RT8 冻结证据为正式性能门 PASS、安全 33/33、可靠性 146/146，以及 feature flag 关闭和开启各 827/827 全量测试。统一结论、实测值和支持矩阵见 `reports/interactive/final_acceptance.md` 与 `reports/interactive/realtime_capability_matrix.json`。

## 故障处理

- `timing_status=DEGRADED`：计算无法维持目标节拍；系统不跳过物理步，应降低倍速或减少并发。
- `SUBSCRIBER_BACKPRESSURE` / `BUFFER_EVICTED`：按 gap 给出的序号续读，必要时降低订阅频率。
- `COMMAND_RATE_EXCEEDED`：等待滚动一秒窗口释放，不要立即重试洪泛。
- `INTERRUPTED`：先验证工作区哈希链，再以初始 TaskSpec、种子和已 ACK 命令日志做确定性重放。
- 未完成或验证失败的工作区不得进入经验库。
