# 测试与验收指南

## 验收分层

| 层级 | 目标 |
| --- | --- |
| 环境 | editable 安装、`pip check`、严格 Doctor |
| 单元与集成 | Schema、Registry、Planner、Runner、API 和证据合同 |
| 物理 | Basilisk 正常、故障、退化、耦合和配对门 |
| Agent | 固定案例、真实 vLLM 调用证据和零回退 |
| 治理 | 脚本、依赖漏洞、发布清单和源码洁净度 |
| 平台 | Ubuntu 核心验收、密封 Run Bundle 和完整性 |

## 判定规则

- 未执行、回退、身份不明、`BLOCKED`、`PENDING` 和 `INCONCLUSIVE` 均不能记为 PASS。
- vLLM 验收必须记录真实调用哈希，且模板/规则回退为零。
- Basilisk 工程仿真批准只覆盖精确合同和已审数据。
- Windows 对当前 Ubuntu 部署目标为 `N/A`，不能从 Linux 验收推导。
- 内部训练与评测资格不代表真实硬件或飞行验证。
- 交互性能 CI 短测不得外推为 30 分钟墙钟或 4 小时仿真长门 PASS。
