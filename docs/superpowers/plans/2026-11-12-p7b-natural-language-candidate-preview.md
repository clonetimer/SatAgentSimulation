# P7-B 第一批：自然语言候选预览与显式应用（2026-11-12）

## 目标
自然语言解析先生成候选 TaskSpec，在对话框内展示字段差异和标准图形流程骨架；用户明确确认后才投影到原生表单，或应用后进入原生图形画布。

## 边界
- 复用现有 `POST /tasks/parse`、TaskSpec 规范化/校验和无损表单投影。
- 候选生成阶段不修改当前 `state.taskSpec`、`state.formData`、当前 Capability 或图形编辑器状态。
- 图形骨架仅为当前 Capability 的标准工作流预览，不宣称服务端 `compile-graph` 已通过。
- 用户确认应用后才调用现有 `projectTaskSpecToForm`；图形正式校验仍需用户在原生画布显式触发。
- 放弃候选不改变当前配置；不自动运行、不生成或执行任意 Python。

## 本批实现
1. Agent 向导按钮改为“生成候选预览”。
2. 递归比较当前 TaskSpec 与候选 TaskSpec，显示最多 80 条差异（界面首屏展示 24 条）。
3. 展示模型能力 ID、任务名和标准图形流程骨架说明。
4. 增加“确认应用候选配置”“应用并查看图形画布”“放弃候选”三个显式动作。
5. 保留原 Agent 工作区直接生成/运行入口的原有行为，只有向导候选预览采用 preview-only 模式。

## 验收
- Node VM 覆盖候选生成不投影、差异生成、丢弃与显式应用状态守卫。
- Python 静态契约测试验证 UI 入口、服务端解析复用、图形校验边界和禁止自动运行。
- 真 Chromium 验证候选生成、字段差异、放弃保持原配置、确认应用后进入配置、应用并打开图形画布。
- 运行现有 Agent/TaskSpec/Graph/Basilisk 回归。
