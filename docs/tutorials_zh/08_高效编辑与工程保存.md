# 08｜高效编辑与工程保存

## 本课目标

减少“画图比建模还费时间”的问题，并学会正确保存工程。

---

# 1. 多选和框选

支持：

```text
Shift / Ctrl / Cmd + 点击   追加/取消选择
空白区域拖动                框选
Ctrl/Cmd + A                全选
```

选中多个对象后拖其中一个，可以整体移动。

---

# 2. 自动布局和对齐

工具栏：

```text
自动布局
左对齐
顶对齐
水平等间距
垂直等间距
```

布局默认吸附到 20 px 网格。

纯布局不会导致生成 Python 过期。

---

# 3. 键盘微调

```text
方向键             20 px
Shift + 方向键      5 px
```

---

# 4. 复制粘贴为什么只允许观察器

V15 允许：

```text
Ctrl/Cmd + C
Ctrl/Cmd + V
Ctrl/Cmd + D
```

复制：

- Scope；
- Display；
- To Workspace。

不允许随意复制物理 slot，例如 EPS、Thermal、Reaction Wheel。

原因是物理模块由父 Capability 合同唯一约束；随意复制会生成没有定义的拓扑。

---

# 5. 撤销 / 重做

```text
Ctrl/Cmd + Z
Ctrl/Cmd + Shift + Z
Ctrl/Cmd + Y
```

---

# 6. 怎么保存工程

建议区分三种东西。

## 6.1 浏览器草稿

适合临时继续工作。

缺点：不适合作为正式工程归档。

## 6.2 `.satgraph.json`

适合保存可编辑图形工程。

建议：重要模型必须导出并放进版本管理。

## 6.3 可运行程序包 ZIP

适合交付和复现运行。

它包含 TaskSpec、图工程、runner、启动脚本和 manifest。

---

# 7. 推荐 Git 管理内容

建议提交：

```text
*.satgraph.json
自定义配置/模板
需要长期保存的导出程序包版本说明
项目文档
```

通常不要提交大量：

```text
runs/
.sat_sim_api/
__pycache__/
临时缓存
```

是否提交完整 Run Bundle 取决于你的试验归档规范。
