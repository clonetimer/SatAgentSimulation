# P9-A 扩展：对象树与单机参量命名治理

## 用户要求

- 默认用户界面删除开发过程文案、内部实现说明和不必要的工程假设面板。
- 参数与输出指标统一采用“单机名称 + 参量名称”。
- 建立“整星 → 分系统 → 单机 → 输出参量/物理参数”的对象树。
- 对象层级必须符合真实卫星结构；地面站、链路预算、数据队列等外部/逻辑对象不得伪装成卫星硬件。
- 轨道与空间环境、轨道控制保持独立；轨道控制目前无独立执行合同，不展示虚假执行能力。

## 实施决策

1. Capability Registry 仍是模型/参数/输出字段的权威来源。
2. 新增独立产品参量字典，逐项登记单机对象、显示名称、源字段、单位、类型、能力合同与 Git blob 来源。
3. 未审定字段不进行 token 翻译猜名，不进入普通用户曲线/指标目录；通过审计报告列出。
4. 组件目录的 24 项是模型类别，不代表真实整星的安装数量。未取得整星硬件清单/实例拓扑之前，不虚构“反作用轮 1..N”等设备数量；只有源遥测字段明确携带设备索引时，才显示编号。
5. 参数配置字段必须关联真实 schema，输出参量必须关联真实 Recorder/observability 字段；单位或 dtype 变化使校验失败。
6. 将地面站、链路预算、数据队列、功率负载、热节点放入“任务环境与逻辑对象”，不挂到卫星物理单机树。
7. “工程假设与适用范围”从默认结果卡片移除，但 Run Bundle/TaskSpec provenance 和验证边界数据保留；不是删除工程证据。
8. V15 保留为独立“专业建模”入口；普通入口命名为“快速仿真”。

## 对象树结构

```
整星
├── 姿态控制分系统
│   ├── 反作用轮组
│   │   ├── 反作用轮组 · 逐轮转动惯量
│   │   ├── 反作用轮 1 · 角速度
│   │   └── 反作用轮 1 · 实际电机力矩
│   ├── 星敏感器
│   ├── 惯性测量单元
│   ├── 磁强计
│   └── 磁力矩器
├── 电源分系统
│   ├── 蓄电池
│   ├── 太阳电池阵
│   └── 配电单元
├── 热控分系统
├── 推进分系统
├── 载荷分系统
├── 通信与数据管理分系统
├── 轨道与空间环境
└── 轨道控制（独立功能对象，尚无独立执行能力）
 
任务环境与逻辑对象
├── 地面站
├── 链路预算
├── 数据队列
├── 功率负载
└── 热节点
```

## 本轮改动范围

- 24 个 component capability 的名称/参数/输出字段字典；
- 对象树构建器与只读 API；
- form schema 使用单机+参量命名；
- 未审定字段不进入普通用户指标/曲线列表；
- UI 文案收敛与默认结果面板简化；
- 浏览器回归改为验证工程 provenance 仍保留、默认不展示工程假设面板；
- 现有 V15 专业建模入口保留。

## 验收

- 24 个 component YAML 的 Git blob 与审定基线一致；
- 所有注册参数与 trace/summary 输出字段均完成单位、dtype 和名称绑定，未审定字段为零；
- 反作用轮等带索引字段明确区分设备编号与 XYZ 轴；
- 对象树严格按父子关系构建，外部/逻辑对象不进入卫星设备树；
- 新 API 只读，不启动仿真、不改变实时服务开关；
- 默认结果面板不出现“工程假设与适用范围”开发/工程说明块，provenance 仍在 Run Bundle；
- 快速仿真入口不再称“拖拽式建模”；V15 作为独立专业入口；
- 现有 API、浏览器、Basilisk 和实时会话回归通过。

## 不在本轮范围

- 不制作/替换卫星 GLB 模型；
- 不启动 CesiumJS 主场景开发；
- 不宣称当前 24 个模型类别就是整星实装设备清单；
- 不新增轨道控制物理闭环或虚构轨道控制器；
- 不改 Basilisk 物理方程、TaskSpec schema、Run Bundle 格式和执行队列。
