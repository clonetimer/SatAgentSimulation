# 06｜运行结果与故障定位

## 本课目标

学会判断“到底是程序没跑起来、验证没通过，还是物理结果不满意”。

---

# 1. 先区分三种状态

## 1.1 Execution / Run Status

最先看：

```text
SUCCEEDED
FAILED
CANCELLED
```

`SUCCEEDED` 表示执行程序完成。

## 1.2 Validation

可能出现：

```text
PASS
FAIL
INCONCLUSIVE
```

它是工程验证结论，不等于进程状态。

例如：

```text
Execution = SUCCEEDED
Validation = INCONCLUSIVE
```

通常表示运行成功，但时间窗或证据不足。

## 1.3 QoI / Metrics

这是“结果好不好”的工程指标。

即使运行成功，QoI 也可能不满足你的目标。

---

# 2. 结果页推荐查看顺序

新手按这个顺序：

```text
1. Execution status
2. Validation
3. QoI / Metrics
4. Telemetry
5. Events
6. Artifacts
7. FMEA / Traceability（有需要再看）
```

---

# 3. Telemetry 怎么看

不要一次打开几十条曲线。

先根据问题搜关键词：

ADCS：

```text
pointing
error
rw
speed
torque
```

EPS：

```text
soc
power
battery
margin
```

Thermal：

```text
temperature
thermal
heat
```

Orbit：

```text
orbit
shadow
environment
```

---

# 4. 运行失败时，画布有什么用

V15 保留**错误回标**，因为它属于建模诊断。

失败时优先：

1. 回到建模画布；
2. 查看红色/错误节点、端口或 binding；
3. 看工作台通知；
4. 再进入结果页看 Events / Validation；
5. 必要时进入 `runs/<run_id>/` 查看 Run Bundle。

---

# 5. 不要用 Scope 替代结果页

Scope 适合：

- 我只关心一条轮速；
- 我正在调一个控制器；
- 我想快速盯住局部状态。

结果页适合：

- 多变量分析；
- QoI；
- 事件；
- 验证；
- FMEA；
- 结果导出与归档。
