# SatAgentSimulation｜卫星数字仿真平台

## 这是什么

用网页配置卫星、分系统或部件，运行基于 Python 和 Basilisk 的工程仿真，查看轨道、姿态、遥测与故障影响，并导出可复核的数据和脚本。普通仿真使用规则向导，不需要写代码或连接 AI；自然语言辅助建模是可选功能。

当前定位是**基本可用、但有明确缺口的工程仿真平台**。适合已注册场景的建模、算法验证与故障对照，模型适用性需结合参数来源和实际运行证据判断。

不知道该读哪份文档，先看[文档地图](docs/DOC_MAP.md)。

## 怎么跑起来

先从[仓库页面](https://github.com/clonetimer/SatAgentSimulation)下载并解压源码，或使用已有克隆；在含有本 README 的项目根目录打开终端。

准备 Windows x86_64 或 Linux x86_64、Python 3.12、已加入 PATH 的 uv，以及 Node.js 22/npm。首次安装和准备三维资源需要联网；当前预编译安装入口不支持 macOS 或其他架构。

依次执行以下三条命令，Windows PowerShell 与 Linux 终端相同：

```text
python scripts/setup_uv.py
python scripts/vendor_scene_assets.py
uv run --no-sync python -m sat_sim.agent_cli serve
```

第一条安装锁定的 Python/Basilisk 环境并检查运行资产；第二条准备本地三维场景资源；第三条启动工作台。三维资源备齐后，场景显示不依赖在线地图服务或地图账号。

浏览器打开 <http://127.0.0.1:8000/>。第一轮在“开始仿真”中选择“运行正常仿真”→“整星”→具体整星对象→“离线仿真”，先保留默认参数，校验后运行，再查看结果曲线。详细界面说明见[工作台使用指南](docs/guides_zh/02_工作台使用指南.md)。

查看本次三维结果时，确认数据来源为“Run 历史结果（已封存）”且对应本次运行；“演示数据（非仿真结果）”只用于观察界面。

运行记录保存在 `runs/`，任务、队列和工作台状态数据保存在 `.sat_sim_api/`；前台终端按 `Ctrl+C` 停止服务。遇到安装或启动问题，查[故障排查指南](docs/guides_zh/09_故障排查指南.md)。

## 能做哪几件事

- 创建和运行目录中已支持的整星、分系统与独立部件任务，调整参数、时长、采样和输出。
- 注入所选模型已开放的故障、退化和运行约束，查看事件响应与效果证据。
- 查看真实整星运行的轨道、姿态和遥测，在三维场景中回放已封存的历史运行；页面会区分演示与真实运行来源。
- 重开历史任务、复用配置、比较同模型运行，下载遥测、报告和完整运行证据包。
- 在高级工作台使用已注册的装配模板、生成 Python、导出可运行程序包，并做有限参数扫描。
- 在服务端开放相应能力后运行限时或持续实时整星会话；需要自然语言辅助时，再按[模型下载与部署](docs/model_distribution.md)配置模型服务。

## 明确不能做什么

- **不能直接代表某颗真实卫星。** 当前没有真实标定数据集；工程参数、固定功率和热份额等假设不能当作地面或飞行标定结果。
- **不能任意扩展模型、故障或工况。** 能力以当前目录和各模型合同为准；例如整星 IMU 信号丢失尚未开放，独立部件的正常运行能力也不等于完整故障能力。
- **不能把所有路径都称为官方原生或完整物理闭环。** 项目仍保留本地工程模型，不同整星模型的电池、热控及资源证据范围也不同；详见[资源范围清单](docs/whole-spacecraft-power-authority.md)。
- **不能凭三维外观认定真实装机关系。** 参考 CAD、几何映射和演示模型不等于经过审定的目标卫星实装配置。
- **不能跨进程恢复整星原物理状态，也不承诺硬实时、硬件在环或飞行级认证。** 异常中止后可保留证据并新建场景；当前发布资格见[发布声明](src/sat_sim/release_manifest.json)。
