# 规则驱动式仿真向导重构设计

## 意图
将普通用户的默认入口从完整工程工作台改为规则驱动的对话式仿真向导。用户通过预定义目标、对象、故障和运行选项逐步完成配置；不需要输入 Prompt，也不调用大语言模型。目标是降低首次使用门槛，同时完整保留高级工作台和 Basilisk-native 执行链。

## 目标
- 默认进入“开始仿真”向导，一次只呈现当前需要回答的问题。
- 提供正常仿真、故障仿真、历史任务、运行对比、高级工作台五个入口。
- 对象和故障选项必须来自现有 Presentation Catalog、Capability Registry 和当前 Schema Event Catalog，不硬编码不存在的模型/故障。
- 复用现有 selectCatalogObject、表单数据、previewForm、runSimulation、任务/运行中心，不新建平行执行后端。
- 用户可返回上一步、重置流程、切换高级工作台。
- 运行前必须调用既有配置校验；校验失败不得运行。
- 运行结果继续使用现有 Run Bundle 和运行结果视图。

## 非目标
- 不做自由文本意图识别，不调用 LLM，不新增模型服务依赖。
- 不改变 Basilisk 模型、物理参数、故障实现、TaskSpec Schema、Durable Queue、Run Bundle 或验证规则。
- 不移除自然语言 Agent、TaskSpec、图形组装、实验中心、目标实验、实时会话等高级功能。
- 第一版不实现自动推荐物理故障或自动修改未在 Registry 中登记的参数。

## 方案比较
1. 在现有三栏页面上增加浮层对话框：改动较小，但复杂页面仍然同时占据注意力。
2. 将向导设为默认独立首页，高级工作台作为单独入口：普通用户默认只看到向导，专业功能完整保留。采用方案 2，最符合“用户面对功能选项”的目标。
3. 全量重写单一聊天应用并替换旧工作台：风险高，会重复实现运行、结果和任务管理，不采用。

## 交互流程
- 欢迎：正常仿真 / 故障仿真 / 历史任务 / 对比运行 / 高级工作台。
- 正常或故障仿真：选择对象层级（整星 / 分系统 / 部件）→ 选择实际可配置对象。
- 故障仿真：从当前对象 Schema 的 fault event catalog 选择故障；用户确认后添加该事件模板，仍由原表单显示和编辑事件参数。
- 配置：设置仿真时长和采样间隔，默认沿用当前模型的 Registry 默认值；其他专业参数和输出仍可进入高级编辑。
- 检查：展示配置摘要，调用现有 previewForm；只有成功后显示“运行仿真”。
- 运行：调用现有 runSimulation，然后进入既有结果面板；不在向导中伪造运行状态或结果。
- 历史和比较：分别跳转现有任务中心、运行中心。

## 状态与数据
向导状态仅为前端会话状态：goal、step、level、objectId、faultEffect、validated。不持久化、不进入 TaskSpec。正式配置只写入既有 state.formData，模型对象由 selectCatalogObject 选择，故障模板由 effectCatalog('fault') 获取，仿真由现有 API/队列执行。

## 约束与可访问性
- 所有显示文本使用中文；选项用 DOM textContent 构建，避免把注册表数据拼入 HTML。
- 每一步有明确标题、返回/重置入口和空状态。
- 不可执行或没有配置能力的对象不允许作为向导选项。
- 故障目录为空时明确提示该对象没有可用的已注册故障，不提供虚构选项。
- 桌面和窄屏均使用单列对话布局。
- 高级工作台保留现有导航与页面 DOM，不通过删除功能来实现简洁。

## 验收
- 默认打开向导，完整工作台不再是默认首页。
- 五个入口路由正确。
- 正常流程可选择 Registry 对象、修改运行时长/采样间隔、预览和运行。
- 故障流程仅列出当前 Schema 中注册的故障，添加后能在原事件列表看到。
- 返回、重置、切换高级模式不丢失既有表单数据。
- 预览失败时运行按钮不可用。
- 现有 Workbench、图形组装、任务/实验/运行中心和真实 Basilisk 有限运行回归不退化。


## 第二阶段：完整对话式仿真操作台
第一版选择对象后曾跳回复杂工作台；该行为不符合产品目标。第二阶段将普通用户流程闭合在同一 wizard shell 内：
- 选择对象后继续选择运行方式：离线仿真、限时实时仿真、持续实时仿真。
- 离线模式：时长/采样、完整注册参数表单（按需展开）、故障事件编辑、QoI 与曲线输出、校验、运行、运行结果/曲线/事件/制品全部嵌入向导。
- 限时实时：复用现有 Interactive Session 创建、启动/暂停/单步/倍速/停止、实时遥测曲线、事件、遥控指令和回执 UI；在 wizard 内嵌控制台，不切换到外部复杂页面。
- 持续实时：复用现有 Continuous Console 创建、启动/暂停/继续/单步/停止归档、遥测曲线与状态面板；在 wizard 内嵌控制台。
- 实时能力由服务端 capabilities policy 决定。当前实时入口只对受支持的 Basilisk 原生整星配置启用；分系统/部件若不支持必须禁用并解释，不做能力降级或参数猜测。
- 用户可以从实时控制台返回向导；离开时明确告知运行会话不会被自动停止。
- 高级工作台保留原始节点；通过 DOM 节点归还机制将参数表单、事件列表、输出选项和结果面板在 wizard 与 creator 间移动，避免重复 DOM ID 和重复业务逻辑。
