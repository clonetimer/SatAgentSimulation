# P9-H：真实整星姿态驱动三维本体

## 目标

在 P9-F 已验收的真实轨道位置与轨迹基础上，增加由真实 Basilisk 整星状态驱动的卫星本体姿态显示。姿态数据必须来自整星刚体状态，而不是星敏感器测量值、控制误差、期望姿态或演示动画。

本阶段先完成姿态真值数据链路、坐标系/旋转约定、姿态可视化和证据验收。单机级三维资产映射作为 P9-I 独立阶段，只有在获得可审计的实体几何和安装锚点后才接入。

## 已有事实与边界

- P9-F 已接通 Basilisk 原生轨道位置遥测，三维地球和轨迹由真实数据驱动。
- 当前卫星本体朝向仍为示意，不代表真实姿态。
- 整星状态 recorder 已持有 Basilisk spacecraft state；状态消息包含位置、速度及 MRP 姿态状态。
- 当前遥测行已输出星敏感器四元数 adcs.star_tracker.q0..q3，该数据是传感器观测，不能直接当作整星真值姿态。
- workbench_scene_catalog.py 对组件的 spatial_anchor 当前全部为 None；对象树明确要求空间锚点必须有资产证据。
- 组件能力类别不等于在轨装机清单，不得据此推导设备数量、安装位置、尺寸或方向。

## P9-H1：姿态数据源与数学契约审计

1. 从真实 Basilisk spacecraft state recorder 明确读取 sigma_BN，记录其定义为 body B 相对 inertial N 的 MRP。
2. 审计 Basilisk MRP 与 quaternion 转换公式、标量在前的分量顺序、主动/被动旋转方向、左右手系和单位。
3. 通过真实运行采样验证 MRP 有限性、转换四元数范数、时间单调性、姿态连续性及退化/奇异情况。
4. 明确区分 truth 姿态、星敏感器测量、姿态控制误差。
5. 禁止把星敏感器观测、姿态误差或控制指令回退为真值姿态。

## P9-H2：原生遥测契约扩展

建议增加显式命名字段：
- attitude.truth.mrp_BN_x/y/z
- attitude.truth.quaternion_BN_q0/q1/q2/q3
- attitude.truth.valid
- attitude.truth.frame（固定为经审定的 N/B 定义）
- 保留原有 orbit.position_m_*、orbit.velocity_m_s_* 和现有传感器字段，不改变其语义。

具体字段在 H1 完成公式和坐标审计后冻结。缺失、非有限、范数异常、序号回退、坐标框架不匹配的姿态数据必须拒绝显示并给出质量状态；不得静默使用默认姿态冒充真实值。

## P9-H3：三维模型姿态驱动

1. 审计 Globe.gl 世界轴：X=90°E、Y=北极、Z=本初子午线赤道；ECEF→Globe 分量映射为 [x_G,y_G,z_G]=[y_E,z_E,x_E]。
2. 坐标链采用显式四元数复合：Basilisk q_BN 为 N→B，先取逆得到 q_NB；GMST 给出 q_EN（N→ECEF）；ECEF→Globe 旋转记为 q_GE；最终 q_GB=q_GE⊗q_EN⊗q_NB。
3. 当前示意模型局部轴按可视化约定定义：+X 沿太阳翼跨度，+Y 指向天线并为太阳翼平面法向，+Z 位于太阳翼平面内。此约定不是 CAD/装配测绘证据。
4. Globe.gl 使用 objectFacesSurface(false)，将 q_GB 转为 XYZ Euler 仅用于其 objectRotation 展示接口；姿态复合本身始终使用单位四元数，不改变物理模型。
5. 位置和姿态使用同一帧、同一 session/stream/sequence 的原子遥测快照，避免新位置配旧姿态。
6. 姿态更新仅改变卫星模型旋转，不改变轨道位置、地面轨迹、相机跟踪或用户相机状态。
7. 在无有效真值姿态时显示明确的“姿态不可用，本体朝向仅为示意”，不把默认朝向标为真实姿态。

## P9-H4：验收

- 单元测试：MRP→quaternion 数学转换、单位范数、零姿态、非零绕轴姿态、接近 MRP shadow-set 边界、非法输入。
- Basilisk 原生测试：从真实 spacecraft state recorder 导出姿态字段，并与独立读取的原始 sigma_BN 对照。
- 浏览器测试：真实 UI 创建限时和持续会话，确认 Globe 收到同一 session/stream/sequence 的真实位置与姿态。
- 封存结果测试：只接受 P9-E 完整性校验通过的 Run Bundle；验证 Run 轨道、姿态真值进入同一数字场景检查器，并保留 Run ID、样本来源与抽样标记。
- 可观测性：场景检查器展示仿真时间、高度、地理位置、MRP、四元数、渲染机体系旋转、session/stream/sequence 和遥测质量；明确标出姿态真值与尚未接入的组合定姿。
- 可交互性：支持跟踪/自由观察/返回全景及机体系 XYZ 坐标轴显隐；切换相机不改变遥测订阅、轨道轨迹或姿态数据。
- A/B 测试：固定历元和轨道位置，施加不同初始姿态/控制响应，验证本体方向随真实姿态变化；只修改渲染坐标映射，不改物理模型。
- 负向测试：缺字段、错误 frame、NaN/Inf、非单位四元数、乱序帧均不更新姿态；已有有效轨道位置链路仍保持一致；未验证 Run 不得进入真实场景状态。
- 证据包包含原始遥测片段、帧身份、转换结果、浏览器渲染截图、交互操作记录和测试报告。

## P9-I：单机空间资产映射（后续独立阶段）

1. 逐一取得真实装配图、CAD/STEP/GLB 资产、安装坐标系、部件局部坐标系和尺寸依据。
2. 由资产/装配来源生成 spatial_anchor，记录来源、版本、单位、坐标系和转换矩阵。
3. 只映射证据完整的部件；未映射对象仍显示在对象树，但不虚构空间位置。
4. 组件资产必须使用经确认的装机实例 ID；Capability 类别不得作为在轨实例数量。
5. 验证父子变换、装配层级、单位换算、部件相对位置及模型包完整性。

## 禁止事项

- 不将星敏感器测量四元数当作 spacecraft truth。
- 不用初始姿态、期望姿态或固定朝向填补缺失真值。
- 不将姿态可视化换算宣称为导航/姿态确定算法精度证明。
- 不修改 Basilisk 物理模型来迎合渲染坐标。
- 不生成没有装配证据的单机空间锚点、部件尺寸、数量或安装姿态。
- 不将 P9-I 资产映射与 P9-H 姿态链路捆绑验收。

## 完成门槛

P9-H 只有在数学契约、Basilisk 原生数据、真实浏览器渲染和负向质量测试全部通过后才可合并。随后单独进入 P9-I。
