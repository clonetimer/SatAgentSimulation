# 01｜先认识三个工作区

## 本课目标

理解 V15 的三个主要工作区，避免一开始就不知道“该在哪儿做什么”。

---

# 1. 图形组装：用来建模

这是你最常用的入口。

里面有两个模式。

## 1.1 任务流程

适合：

- 运行一个已有 Capability；
- 配置参数；
- 注入事件；
- 生成 Python；
- 执行任务。

它更像：

```text
模型
 ↓
参数
 ↓
事件
 ↓
输出
 ↓
代码
 ↓
运行
```

如果你只是“我要跑这个已有模型”，优先用任务流程。

## 1.2 多模块装配 · V15

适合：

- 类 Simulink 的模块化视图；
- 替换兼容模块；
- 看正式 signal binding；
- 加 Scope / Display / To Workspace；
- 做 baseline / replacement 对比。

它更像：

```text
模块 A ─signal─→ 模块 B
   │
   └──────────→ Scope
```

如果你的问题是“这些模块怎么组成一个模型”，优先用多模块装配。

---

# 2. 运行与结果：用来分析

这里负责完整结果，不负责建模。

你会在这里看：

- QoI / Metrics；
- Telemetry；
- Events；
- Validation；
- FMEA；
- Fault Traceability；
- Run Bundle artifacts；
- 数据下载；
- 报告。

记住一句话：

> **模型图保持干净，复杂结果去结果页。**

---

# 3. Scope / Display / To Workspace：局部观察

这三个东西虽然放在模型图上，但它们不是物理模块。

## Scope

用途：看曲线。

## Display

用途：看最近一次运行的末值。

## To Workspace

用途：把一条已记录 telemetry 导出 CSV / JSON。

三者都不会：

- 改变 TaskSpec；
- 改变 solver；
- 占用物理 fan-out；
- 进入生成的物理 Python。

---

# 4. 新手暂时不需要理解的词

你会在界面或文档中看到：

```text
Capability
TaskSpec
binding
simulation_ports
module contract
fingerprint
```

第一次使用可以先这样理解：

| 名词 | 新手理解 |
|---|---|
| Capability | 平台已经注册好的“可运行能力” |
| TaskSpec | 图形模型编译后的标准任务说明 |
| binding | 两个物理模块之间的正式信号连接 |
| simulation_ports | 模块允许输入/输出什么信号 |
| module contract | 什么模块允许替换什么位置 |
| fingerprint | 合同版本指纹，防止旧工程偷偷使用新语义 |

真正需要深入时再学习第 10 课。

---

# 5. 一个选择规则

以后不知道该去哪里时，按这个判断：

```text
我要搭模型/改参数？
  → 图形组装

我要看完整运行数据？
  → 运行与结果

我只想盯一两条局部信号？
  → Scope / Display

我要把模型交付给别人运行？
  → 导出可运行程序包
```
