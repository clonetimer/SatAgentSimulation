# 开发者指南

## 1. 核心目录

```text
src/sat_sim/          Agent、TaskSpec、Registry、API、队列和执行器
src/components/       部件模型
src/subsystems/       分系统模型
src/whole_spacecraft/ 整星装配、耦合、QoI 和运行器
configs/              认证、Provider、参数、校准和验证配置
examples/             TaskSpec 和场景示例
evals/                Agent 评测集
scripts/              发布、审计、浏览器和评测脚本
tests/                自动化测试
deploy/production/          systemd 和 Nginx 模板
third_party/           WMM/SPICE 运行资产
```

## 2. 核心调用链

```text
UnifiedAgentRequest
→ Capability Registry
→ CanonicalTaskSpec
→ validate_task_spec
→ resolve_task_spec
→ plan_task_spec
→ prepare_run
→ DurableExecutionQueue
→ local/remote Worker
→ execute_prepared_run
→ verify_run_bundle
```

## 3. 新增 Capability

至少需要：

1. 稳定的 `capability_id`；
2. 输入 Schema；
3. builder/runner 入口；
4. 依赖声明；
5. 故障/退化支持范围；
6. 输出和 QoI；
7. 限制与保真度声明；
8. 示例 TaskSpec；
9. 正常、异常和边界测试；
10. Operator Effect→QoI 显式合同。

不要让 Agent 通过 Prompt 声明代码库不存在的能力。

## 4. 新增故障或退化

- 故障应作用到真实部件参数或 Basilisk 消息链；
- 退化应在构建时或明确的运行时路径生效；
- 必须记录注入时间、目标、前后参数和恢复；
- 必须提供方向性 QoI 或物理效果证据；
- 禁止通过修改结果表格伪造故障效果。

## 5. API 开发

应用工厂：

```python
from sat_sim.api import create_app
app = create_app()
```

新增写接口时必须：

- 通过 Pydantic 严格模型；
- 配置最小 RBAC；
- 不返回服务器绝对路径；
- 记录审计事件但不记录 Token、密钥或完整 Prompt；
- 限制请求体、上传体和路径解析；
- 为错误状态提供稳定错误码。

## 6. 测试

```bash
pytest -q
ruff check src tests scripts
ruff check --select F811,F841 .
```

针对长时 Basilisk 测试，可按测试文件分批执行并保留日志；不能以命令通道超时代替测试通过。

## 7. 发布身份

发布身份同时存在于：

- `pyproject.toml`；
- `src/sat_sim/release_manifest.json`；
- OpenAPI/API 版本；
- Wheel 文件名；
- 发布验证报告。

升级版本时必须同步更新并执行 Release Closure。
